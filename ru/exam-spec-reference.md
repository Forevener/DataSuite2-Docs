# Справочник по спецификации экзамена

Генератор экзаменов работает по **спецификации** — документу JSON5, который описывает генеральную совокупность, а не набор данных. Данные каждого студента разыгрываются из этой совокупности, и зерном генератора служит имя студента. Числа у каждого получаются свои, а заданная вами структура (факторы, эффекты, пропуски) одна для всех.

Одна и та же спецификация служит обеим кнопкам раздела. Кнопка **Экспортировать экзаменационную ссылку** превращает её в ссылку `?exam=`, которую открывают студенты. Кнопка **Загрузить тестовые данные в приложение** разыгрывает один набор данных и сразу загружает его в DataSuite: так проверяют модуль на данных с заранее известными свойствами.

> Эта страница посвящена набору данных. Оцениваемые вопросы к нему описаны в [справочнике по вопросам экзамена](./exam-question-reference.md), а то, что видит студент, — на странице [Прохождение экзамена](./taking-an-exam.md).

## Быстрый старт

```json5
{
	n: 200,
	factors: ["Physical", "Mental"],
	phi: { "Physical~Mental": 0.3 },
	defaults: { family: "beta", params: [2, 5], min: 0, max: 100, round: 0 },
	variables: {
		PF: { load: "Physical*0.80" },
		GH: { load: "Physical*0.55 + Mental*0.25" },
		MH: { load: "Mental*0.80" },
	},
	groups: {
		sex: { levels: ["F", "M"], effect: "Physical*-0.6" },
	},
}
```

Это полная спецификация: два коррелирующих латентных фактора, три измеряющие их шкалы опросника со скошенным распределением баллов от 0 до 100 и различие между полами в 0.6 стандартного отклонения по фактору Physical.

JSON5 допускает ключи без кавычек, комментарии и запятую после последнего элемента, поэтому пишите спецификацию как код, а не как конфигурационный файл.

Нажмите **Сформировать просмотр**, чтобы разыграть набор данных одного студента и увидеть реализованные значения, а затем **Пересоздать**, чтобы сменить зерно и посмотреть, насколько они меняются от студента к студенту. **Вернуть пример** восстанавливает стартовую спецификацию с комментариями, в которой задействована большая часть полей с этой страницы.

## Два шаблона

Спецификация бывает одного из двух видов, и вид определяется тем, какой ключ в ней есть.

| Шаблон | Признак | Форма | Чем анализировать |
|---|---|---|---|
| Факторная модель | `factors` + `variables` | Широкая — строка на наблюдение, столбец на переменную | Всеми модулями: описательная статистика, корреляции, сравнение, факторный анализ, надёжность, регрессия, анализ времени до события |
| План эксперимента | блок `design` | Длинная — строка на каждую пару «испытуемый × замер», со столбцом идентификатора `subject` | [Сравнительный анализ](./comparison-analysis.md) — межгрупповой дисперсионный анализ, анализ с повторными измерениями, смешанный план и MANOVA |

Факторная модель служит психометрии: наблюдаемые индикаторы нагружаются на латентные переменные. Шаблон плана служит эксперименту: он задаёт средние по ячейкам скрещённых факторов. Шаблоны не дополняют, а исключают друг друга: если в спецификации есть `design`, ключи факторной модели полностью игнорируются.

## Поля, которые есть у любой спецификации

| Поле | Значение |
|---|---|
| `n` | Объём выборки, по умолчанию 200. В плане эксперимента это число **испытуемых**, а число строк равно `n × within-cells`, то есть числу испытуемых, умноженному на число замеров |
| `id` | Необязательное название экзамена. Оно попадает в строку о происхождении данных в экспортированном документе Word (только в факторной модели) |
| `exam` | Оцениваемые вопросы — см. [справочник по вопросам экзамена](./exam-question-reference.md) |

## Факторная модель

### Факторы и их корреляции

```json5
factors: ["Physical", "Mental"],
phi: { default: 0.3, "Physical~Mental": 0.45 },
paths: { "Physical->Mental": 0.4 },
```

- `factors` — имена латентных переменных. Сами факторы в столбцы не попадают, в данных появляются только нагруженные на них индикаторы.
- `phi` — корреляции между факторами. Одно число задаёт корреляцию для всех пар, а в записи `{ default: 0.3, "A~B": 0.45 }` пары задаются по отдельности. Если поле опущено, факторы не коррелируют.
- `paths` — направленные пути между факторами, которые превращают модель измерения в [структурную](./structural-equation-modeling.md). Запись `{ "Physical->Mental": 0.4 }` делает фактор Mental зависимым от Physical, поэтому предиктор, влияющий на Physical, действует на Mental **косвенно**, и получается настоящий набор данных для анализа медиации. Модель должна быть рекурсивной (без циклов): петля обратной связи отклоняется, и сообщение называет её. Когда задано `paths`, `phi` означает корреляцию между *возмущениями*, а не между самими факторами.

> **Медиация — произведение двух путей.** Косвенный эффект равен наклону предиктора на Physical, умноженному на путь Physical→Mental. Измерение ослабляет оба, поэтому реализованный коэффициент, который студент получит в [регрессии](./regression-analysis.md), меньше заданного. Загрузите тестовые данные и постройте модель, чтобы увидеть значение, о котором вы на самом деле спрашиваете.

### Переменные

Каждая запись в `variables` — один наблюдаемый индикатор. Поле `load` — факторное выражение с нагрузками индикатора на каждый фактор, и перекрёстные нагрузки задаются так же, как основные. У пункта развёртывания фактор вместо этого указывается в поле `factor` — см. [пункты развёртывания](#пункты-развёртывания).

```json5
defaults: { family: "beta", params: [2, 5], min: 0, max: 100, round: 0 },
variables: {
	PF: { load: "Physical*0.80" },
	GH: { load: "Physical*0.55 + Mental*0.25", family: "normal", params: [50, 10] },
	MH: { load: "Mental*0.80", params: [5, 2] },
},
```

`defaults` — выходное распределение, которое наследуют все переменные. Любое из полей `family`, `params`, `min`, `max`, `round` можно переопределить у отдельной переменной. Имена факторов в выражении `load` не должны содержать `+`, `−` и `*`.

> **Остаточная дисперсия вычисляется, а не задаётся.** Нагрузки индикатора определяют, какую долю его дисперсии объясняют факторы, а остальное приходится на шум и вычисляется как `1 − h²`. Если нагрузки объясняют почти всю дисперсию, индикатор становится почти детерминированной функцией факторов, и просмотр об этом предупреждает.

### Блоки пунктов

Шкале опросника из десятка пунктов не нужен десяток записей. Поле `count` создаёт блок, а **массив** наборов превращает его в перемешиваемый блок.

```json5
variables: {
	WB: [
		{ count: 6, load: "Mental*0.65", jitter: 0.06 },
		{ count: 2, load: "Mental*-0.6" },
	],
},
```

- `count` — запись `WB: { count: 8, load: "Mental*0.7" }` создаёт пункты `WB1` … `WB8`.
- Если задан **массив наборов**, он перемешивается для каждого студента отдельно: пункты тасуются внутри блока, поэтому набор с **отрицательной** нагрузкой (обратный пункт) у каждого студента оказывается под своим именем. Ответ на вопрос «какие пункты обратные?» тогда приходится искать в таблице удаления пунктов модуля [надёжности](./reliability-analysis.md), и передать его другому студенту нельзя.
- `jitter: 0.06` разбрасывает нагрузки внутри набора на случайную величину, которая определяется зерном и фиксируется при составлении спецификации, поэтому спецификация от запуска к запуску остаётся прежней. `loadRange: [0.8, 0.4]` вместо этого задаёт линейный градиент нагрузок по набору (только для нагрузок на один фактор).
- `deltaRange: [-1.5, 1.5]` так же линейно распределяет идеальные точки набора [пунктов развёртывания](#пункты-развёртывания), перезаписывая δ в `params` у каждого пункта. У наборов других семейств это поле отклоняется, а набор пунктов развёртывания не принимает `loadRange` и `jitter`.

> Обратный пункт — не особая настройка, а просто набор с отрицательной нагрузкой. Во всём остальном это обычный пункт.

### Семейства распределений

Стандартизованное латентное значение каждой переменной проходит через обратную функцию распределения и получает нужное маргинальное распределение. Параметры в `params` задаются по позиции, у каждого семейства свой набор.

| Семейство | `params` | Примечания |
|---|---|---|
| `normal` | среднее, ст. откл. | Семейство по умолчанию. Без `params` — (0, 1) |
| `beta` | shape1, shape2 | Масштабируется в `[min, max]`, поэтому задайте оба. Естественный выбор для балла по ограниченной шкале |
| `gamma` | shape, rate | Положительные значения, скошенность вправо |
| `lognormal` | meanlog, sdlog | Положительные значения, более тяжёлый правый хвост |
| `poisson` | lambda | Счётные данные |
| `negbin` | среднее, size | Счётные данные с избыточной дисперсией |
| `zip` | lambda, доля нулей | Пуассоновское с избытком нулей |
| `zinb` | среднее, size, доля нулей | Отрицательное биномиальное с избытком нулей |
| `ordinal` | пороги… | Точки разреза на латентной шкале → коды Ликерта 1, 2, 3, … |
| `ggum` | дискриминация, идеальная точка, широты… | Коды Ликерта 1, 2, 3, … для пунктов развёртывания. Широты задаются так, как их выводит таблица модуля IRT (= −τ в обозначениях Робертса). Фактор указывается в поле `factor`, а не `load` — см. [пункты развёртывания](#пункты-развёртывания) |
| `skew-normal` | положение, масштаб, форма | Настоящая асимметрия без ограничения значений |
| `t` | df, положение, масштаб | Тяжёлые хвосты. Положение и масштаб необязательны |
| `mixture` | вес, среднее, ст. откл. × ≥ 2 | Многомодальное: по тройке параметров на компоненту |
| `binomial` | size, вероятность | `size: 1` даёт исход 0/1 для логистической регрессии |
| `bernoulli` | вероятность | Сокращённая запись `binomial(1, prob)` |
| `exponential` | rate | Время до события (без памяти) |
| `weibull` | shape, scale | Время до события |
| `loglogistic` | shape, scale | Время до события |
| `gompertz` | shape, rate | Время до события (риск растёт со временем) |

`min` и `max` ограничивают выходные значения, а `round` задаёт число знаков после запятой. Все три поля применяются после преобразования семейства. Исключения — `beta`, значения которого и так лежат в диапазоне, и `ordinal` с `ggum`, чьи коды категориальны. Именно ограничение скапливает значения на потолке или на полу, и просмотр показывает их долю как `%=max`.

> **Ненормальные маргинальные распределения искажают корреляции.** Латентная структура в точности такая, какую вы задали, но нелинейное преобразование к маргинальному распределению сдвигает корреляцию Пирсона от заданного значения. Сильнее всего это заметно у бинарных исходов, где максимум коэффициента φ меньше 1. Ранговая структура сохраняется. Главным образом поэтому ключом ответов служат реализованные значения из просмотра, а не спецификация.

### Пункты развёртывания

Пункт семейства `ordinal` — пункт доминирования: чем выше значение фактора, тем сильнее респондент согласен. Пункт `ggum` — пункт **развёртывания** (идеальной точки): согласие максимально там, где позиция респондента совпадает с позицией утверждения, и спадает в обе стороны. Такие пункты описывает модель [GGUM в модуле IRT](./irt-analysis.md#b-ggum-polytomous-unfolding).

```json5
factors: ["Attitude"],
variables: {
	Moderate: { factor: "Attitude", family: "ggum", params: [1.5, 0.2, 1.6, 1.1, 0.5] },
	Stance: [
		{ count: 3, factor: "Attitude", family: "ggum", params: [1.5, 0, 1.6, 1.1, 0.5], deltaRange: [-1.5, -0.3] },
		{ count: 3, factor: "Attitude", family: "ggum", params: [1.5, 0, 1.6, 1.1, 0.5], deltaRange: [0.3, 1.5] },
	],
},
```

- `factor` вместо `load` указывает единственный фактор, к которому относится пункт. У пункта развёртывания нет линейной нагрузки, поэтому `load` вместе с `factor` отклоняется.
- `params` — `[a, δ, t1, …, tC]`: дискриминация (положительная), идеальная точка на факторе с единичной дисперсией и C ≥ 1 широт, которые дают коды от 1 до C + 1 (при C = 1 пункт бинарный). Ответы разыгрываются по функции отклика самой GGUM в параметризации mirt, поэтому подгонка GGUM в модуле IRT восстанавливает эти значения. Широты записываются в том виде, в каком таблица модуля выводит их в столбцах **Широта {n}**, то есть как −τ в обозначениях Робертса.
- `deltaRange` распределяет идеальные точки набора по пунктам (см. [блоки пунктов](#блоки-пунктов)). Массив наборов, как в примере, перемешивает утверждения для каждого студента, и их порядок нельзя восстановить по именам.
- Групповые эффекты, предикторы и `paths` действуют на пункт через его фактор, как и на любой индикатор.
- `min`, `max` и `round` игнорируются, как у `ordinal`. Отклоняются: `ggum` как семейство в `defaults`, у предиктора, у исхода плана эксперимента и у конкурирующего риска; `labels`, `censor` и `mnar` у самого пункта; ссылка `on` механизма `mar` на этот пункт.

> **Держите идеальные точки в пределах ±1.5.** Положение утверждения определяют только респонденты по обе его стороны, а на факторе с единичной дисперсией мало кто выходит за ±2. Просмотр об этом предупреждает (см. [защитные проверки](#защитные-проверки)).

### Метки

`labels` задаёт названия уровней исхода семейства `binomial` и превращает числовой столбец в категориальный.

```json5
Remission: { load: "Mental*0.70", family: "bernoulli", params: [0.4], labels: ["No", "Yes"] },
```

Без этого поля столбец остаётся обычным столбцом 0/1 — такой и нужен, если студент должен построить по нему логистическую регрессию. Меток столько же, сколько уровней, поэтому при `size: 1` их две.

### Пропущенные данные

`missing` вносит пропуски в переменную или предиктор. Как и всё остальное, пропуски определяются зерном, то есть именем студента.

```json5
missing: 0.2,
missing: { mechanism: "mar", rate: 0.12, on: "age", slope: 0.8 },
```

- Просто число — доля пропусков по механизму MCAR.
- `mechanism: "mar"` ставит пропуски в зависимость от **другого** столбца, указанного в `on`, а `"mnar"` — от значения самой переменной. `slope` задаёт силу этой зависимости в логит-шкале.
- `rate` — базовая доля пропусков. При ненулевом `slope` реализованная доля от неё отличается, и просмотр показывает реализованный процент пропусков.

Какие наблюдения войдут в анализ, зависит от [настройки пропущенных данных](./settings.md#пропущенные-данные) у студента, так что спецификация с пропусками заодно проверяет, заметил ли он их.

### Время до события

`censor` превращает переменную в исход типа «время до события» и выводит два столбца: `<name>` (наблюдаемое время) и `<name>_event` (статус: `0` — цензурировано, `1` — событие, `2…` — номер конкурирующей причины). Для этого нужно одно из семейств времени до события.

```json5
TimeToRelapse: { load: "Mental*0.6", family: "weibull", params: [1.3, 40], censor: { mechanism: "random", rate: 0.02 } },
```

| `mechanism` | Дополнительные поля | Что делает |
|---|---|---|
| `random` | `rate` | С событием конкурирует экспоненциальное время цензурирования |
| `fixed` | `at` | Административная отсечка: все, кто к этому моменту ещё под риском, цензурируются |
| `type2` | `events` | Наблюдение прекращается после k событий, все остальные цензурируются |
| `competing` | `risks`, необязательно `at` | Независимые конкурирующие причины, у каждой своё семейство и параметры. Срабатывает та, что наступит раньше |

Ковариаты масштабируют время (модель ускоренного времени отказа, AFT, а не модель пропорциональных рисков Кокса), поэтому в [анализе времени до события](./time-to-event-analysis.md) студент получит реализованное отношение рисков. Просмотр показывает реализованную долю событий, медианное время и долю цензурированных наблюдений.

### Категориальные группы

```json5
groups: {
	condition: { levels: ["Healthy", "Chronic"], effect: "Physical*-0.8 + Mental*-0.3", spread: [1, 1.5] },
	sex: { levels: ["F", "M"] },
},
groupPhi: { "condition~sex": 0.35 },
```

- `levels` — метки уровней, которые выводятся категориальным столбцом.
- `effect` — факторное выражение, которое сдвигает средние факторов между соседними уровнями в единицах стандартного отклонения фактора. Для двух уровней это непосредственно d Коэна, для большего числа — сдвиг на один шаг при центрированных уровнях.
- `spread` — множители по одному на уровень: каждый масштабирует только **дисперсию** своего уровня. Группы могут различаться разбросом, не различаясь средним, и именно это делает осмысленным вопрос о выборе между критериями Уэлча и Стьюдента.
- `groupPhi` — связь категориальных переменных между собой, чтобы нулевая гипотеза критерия независимости χ² для любых двух из них не выполнялась по построению. Запись та же, что у `phi`. Поле задаёт латентную корреляцию, стоящую за категориальными переменными, а ключом ответов служат реализованные χ² и V Крамера.

### Непрерывные предикторы

Предикторы — ковариаты, которые сдвигают средние факторов, то есть непрерывный аналог группового `effect`. Кроме того, каждый предиктор выводится отдельным столбцом.

```json5
predictors: {
	age:    { family: "normal", params: [40, 12], effect: "Physical*-0.5" },
	visits: { family: "negbin", params: [4, 2],   effect: "Physical*-0.3" },
},
predictorPhi: { "age~visits": 0.3 },
interactions: { "age:condition": "Physical*-0.3" },
```

- `effect` — наклон по латентному фактору в единицах стандартного отклонения.
- Предикторы **не** наследуют `defaults`: бета-распределение от 0 до 100 по умолчанию сделало бы «возраст» бессмысленным. Поэтому у каждого предиктора свои `family` и `params`, по умолчанию нормальное распределение (0, 1).
- `predictorPhi` — корреляции между предикторами, запись та же, что у `phi`. Именно так задаётся мультиколлинеарность.
- `interactions` — члены-произведения. Ключ соединяет через `:` имена двух предикторов или групп, а значение — наклон модерации по фактору. Порядок взаимодействия может быть любым.

> **Наклон действует на фактор, а не на индикатор.** Поэтому регрессия отдельного индикатора на предиктор восстанавливает примерно произведение нагрузки на наклон, `loading × slope`, ослабленное измерением. Если коэффициент регрессии должен получиться ровно таким, как вы задали, дайте исходу собственный фактор с единственным индикатором и нагрузкой около 1.

### Кластерная структура

Наблюдения вложены в кластеры (пациенты в клиники, ученики в классы), со случайными свободными членами по факторам и, если нужно, со случайным наклоном.

```json5
clustering: {
	cluster: "clinic", nClusters: 12,
	intercept: "Physical*0.4 + Mental*0.3",
	slope: { predictor: "age", factor: "Physical", sd: 0.15, corr: 0.3 },
	sizes: [30, 20, 20, 10],
},
```

- `cluster` / `nClusters` — имя выводимого столбца идентификатора и число разыгрываемых кластеров. `sizes` задаёт размеры кластеров явно вместо равного деления.
- `intercept` — стандартное отклонение случайного свободного члена кластера по каждому фактору. Оно и создаёт внутрикластерную корреляцию. Реализованный ICC показывает просмотр.
- `slope` — необязательный случайный наклон одного предиктора для одного фактора, со своим стандартным отклонением `sd` и корреляцией `corr` со свободным членом.

Кластер, предиктор времени и случайный наклон вместе дают модель роста в длинном формате.

### Временные ряды

Блок `timeseries` заменяет независимые одинаково распределённые возмущения факторов процессом SARIMA на временном индексе.

```json5
timeseries: {
	time: "week", order: [1, 1, 1], ar: [0.6], ma: [-0.3],
	seasonal: [1, 0, 0], sar: [0.4], period: 12,
	unit: "store", units: 24,
	start: "2020-01-06", step: "week",
},
```

- `time` — имя выводимого столбца времени. `order` задаёт `[p, d, q]`, а `seasonal` — `[P, D, Q]` с периодом `period`, по одному коэффициенту на порядок в `ar` / `ma` / `sar` / `sma`.
- `unit` + `units` превращают ряд в панель и выводят столбец идентификатора единицы (`sizes` задаёт длину ряда каждой единицы). Задайте оба поля или ни одного. Без них получится одиночный ряд Бокса — Дженкинса или ряды унаследуют группировку из `clustering`.
- `start` (дата `YYYY-MM-DD`) + `step` (`day`, `week`, `month`, `quarter` или `year`) выводят временной индекс настоящими датами, а не целыми числами. Задайте оба поля или ни одного. Это важнее, чем кажется: [анализ временных рядов](./time-series-analysis.md) определяет сезонный период по шагу столбца и может сделать это только для столбца, который распознаётся как дата. Простой целочисленный индекс всегда даёт частоту 1.

Интегрированный ряд (`d` или `D` больше 0) нестационарен и не имеет фиксированной дисперсии, поэтому оставляйте его индикаторам маргинальное распределение `normal`. Возмущения всех факторов порождает одна общая структура, а ключом ответов служит реализованная автокорреляция первого порядка в просмотре. На коротких панелях она смещена вниз: это свойство оценки на малых выборках, а не ошибка генератора.

### Явная матрица нагрузок

Поле `loadings` верхнего уровня принимает обычную матрицу «строки × факторы» и полностью заменяет выражения `load`. Оно служит для сохранения и повторной загрузки спецификации без потерь, а также для вставки матрицы из статьи. С блоками пунктов его сочетать нельзя: сопоставить строки матрицы с пунктами блока невозможно.

## Экспериментальные планы

Чтобы получить данные в длинном формате для дисперсионного анализа и MANOVA, задайте блок `design` вместо `factors` / `variables`.

```json5
{
	n: 60,
	design: {
		between: { group: ["control", "treat"] },
		within: { time: ["pre", "mid", "post"] },
		outcomes: {
			anxiety: { mean: 50, sd: 10, effect: "group*0.6 + time*0.4 + group:time*0.5" },
			mood:    { mean: 20, sd: 4,  effect: "time*-0.3" },
		},
		cov: { type: "ar1", rho: 0.5 },
		outcomeCov: { "anxiety~mood": -0.4 },
	},
}
```

| Поле | Значение |
|---|---|
| `between` | Межгрупповые факторы. Каждый испытуемый попадает в одну ячейку, и все сочетания уровней заполняются поровну |
| `within` | Факторы повторных измерений, полностью скрещённые у каждого испытуемого. На каждую ячейку приходится строка, а испытуемого обозначает столбец идентификатора |
| `outcomes` | Зависимые переменные, по записи на каждую |
| `cov` | Ковариация между замерами $\Sigma_W$ |
| `outcomeCov` | Корреляция между исходами для MANOVA с несколькими зависимыми переменными, запись та же, что у `phi`. Если поле опущено, исходы независимы |
| `subject` | Имя столбца идентификатора испытуемого, по умолчанию `subject`. Выводится, только если есть факторы повторных измерений |

Плану нужен хотя бы один фактор `between` или `within` и хотя бы один исход. План только с повторными измерениями допустим.

### Исходы

Исход семейства `normal` принимает `mean` и `sd`, а также либо выражение `effect`, либо таблицу `cells`. Исход любого другого семейства (`family`) принимает `params` и проходит через то же преобразование NORTA, что и в факторной модели, поэтому `mean`, `sd` и `cells` есть только у нормального исхода.

- `effect` — выражение в единицах d Коэна, составленное из имён межгрупповых факторов и факторов повторных измерений. Знак `:` задаёт член взаимодействия: `"group*0.6 + time*0.4 + group:time*0.5"`. Это самый экономный способ, и он используется по умолчанию.
- `cells` — явная таблица средних по ячейкам с ключами из меток уровней через запятую. Она нужна для закономерности, которую не описать линейным выражением: `{ "control,pre": 48, "control,post": 52 }`.
- `missing` и `labels` работают у каждого исхода так же, как у переменной факторной модели, но ссылка `on` механизма `mar` указывает на другой **исход**.

> **Межгрупповые эффекты здесь воспроизводятся точно.** Средние по ячейкам детерминированы, поэтому заданное d = 0.6 и в генеральной совокупности равно 0.6: нет нагрузки, которая могла бы его ослабить. Это единственное место генератора, где заданное и популяционное значения совпадают. Ненормальные маргинальные распределения и критерии, зависящие от корреляции между замерами, всё равно дают реализованные значения, отличные от заданного.

### Ковариация между замерами

`cov` — одна матрица, которую можно задать тремя способами:

| Форма | Значение |
|---|---|
| `{ type: "cs", rho: 0.6 }` | Составная симметрия: одна и та же корреляция между любыми двумя ячейками. Вариант по умолчанию, при ρ = 0.5 |
| `{ type: "ar1", rho: 0.5 }` | $\rho^{\vert i - j \vert}$: соседние моменты времени коррелируют сильнее далёких. Нужен единственный упорядоченный фактор повторных измерений |
| `{ "pre~post": 0.4 }` | Неструктурированная матрица, ключи — метки замеров |

Матрица задаётся для нормальной латентной переменной, поэтому для нормальных исходов она точна, а для остальных искажается.

Анализируйте результат в [модуле сравнительного анализа](./comparison-analysis.md): межгрупповые факторы соответствуют группирующей переменной, факторы повторных измерений — условию, а столбец испытуемого — идентификатору испытуемого. Модуль работает именно с такой раскладкой данных, так что преобразовывать их не нужно.

## Реализованное, а не заданное

Каждое число в спецификации описывает генеральную совокупность. Студент анализирует одну выборку из неё, поэтому реализованная корреляция 0.42 при заданной 0.45 — не ошибка, а выборочная изменчивость, благодаря которой набор данных у каждого студента свой. Отсюда два следствия, которые стоит запомнить.

**Ключ ответов — просмотр, а не спецификация.** Если между тем, что вы написали, и тем, что появилось в столбце, стоит нелинейное маргинальное преобразование, модель измерения или преобразование NORTA, значение имеет реализованная величина. Постройте просмотр и сверьтесь с ним.

**Значимость не задаётся, а возникает.** Вы задаёте размеры эффектов, а преодолеет ли t-критерий конкретного студента порог α, зависит от его выборки. Это достоинство: ответом «переменные 1 и 3» нельзя поделиться с другими студентами. Но эффект у самого порога превращает вопрос в лотерею, поэтому задавайте эффекты заметно дальше от нуля, если изменчивость не входит в замысел задания.

## Защитные проверки

Генератор проверяет спецификацию, прежде чем разыграть данные, и сообщает о проблеме там, где её можно исправить:

- Корреляционная матрица (`phi`, `predictorPhi`, `groupPhi`, `outcomeCov`), которая не является положительно определённой, отклоняется заранее с указанием её имени, а не всплывает посреди розыгрыша необработанной ошибкой решателя.
- Просмотр предупреждает, когда нагрузки почти не оставляют индикатору остаточной дисперсии и он становится почти детерминированной функцией факторов. Если это не было задумано, уменьшите нагрузки.
- Просмотр предупреждает, когда за идеальной точкой пункта развёртывания ожидается меньше 10 респондентов: $n\,\Phi(-|\delta|) < 10$ на факторе с единичной дисперсией, без учёта сдвигов от групп и предикторов. При n = 200 это любое |δ| больше примерно 1.65. Пункт развёртывания идентифицируется только респондентами по обе его стороны, поэтому сдвиньте δ к 0 или увеличьте `n`.
- Неизвестные имена факторов, некорректные выражения мини-языка, неверное число параметров семейства и цикл в блоке `paths` — обо всём этом сообщается с именем записи, которая вызвала ошибку.

## Советы

**Составляйте вопросы по реально разыгранным данным.** Напишите спецификацию, постройте просмотр, затем напишите блок `exam` и нажмите **Вычислить ключ ответов**. Вопрос хорош ровно настолько, насколько хороши реализованные данные, на которых он построен: если при каждом пересоздании ответом на вопрос-множество оказывается вся область, эффекты слишком велики.

**Одна ссылка — один блок заданий.** Ссылка содержит один набор данных. Вопросам, которым нужна другая структура (повторные измерения, другая группирующая переменная, другой инструмент), место в отдельной ссылке с собственной спецификацией.

**Подписывайте экзамен полем `id`.** Оно попадает в строку о происхождении данных в экспортированном документе, и по ней видно, к какому заданию относится присланный файл.

**Пересоздавайте перед экспортом.** Набор значимых результатов должен меняться от студента к студенту. Если он не меняется никогда, у всех студентов одинаковые ответы, и защиты от списывания больше нет.

**Тестовые данные — инструмент отладки.** Всё, чего не показывает просмотр (реализованное взаимодействие, косвенный эффект, ICC по конкретному индикатору), можно измерить в самом приложении, нажав **Загрузить тестовые данные в приложение**.

## Что выбрать

**Факторная модель или план эксперимента?** Если вопрос касается измерения (надёжности, факторной структуры, корреляций между шкалами), нужна факторная модель. Если речь об эксперименте с условиями и ячейками, нужен план. Яснее всего различие видно на повторных измерениях: шаблон плана выводит длинный формат, с которым модуль сравнительного анализа работает напрямую, а факторная модель дала бы широкие столбцы, и студенту пришлось бы сначала их преобразовать.

**`effect` или `cells`?** Выражение `effect` короче и нагляднее: главные эффекты и взаимодействия в единицах d. Переходите к `cells`, только когда закономерность нелинейна: перекрёстное взаимодействие, выход на плато, одна выбивающаяся ячейка.

**`groups` или `predictors`?** Группа категориальна и выводит уровни, предиктор непрерывен и выводит число. Оба сдвигают средние факторов, так что выбор зависит только от того, какой анализ должен выполнить студент: сравнение или регрессию.

**Блок пунктов или перечисление?** Перечисляйте пункты, пока каждый заметно отличается от других. Переходите на блок, как только пункты становятся вариациями одной нагрузки, а при появлении обратных пунктов берите массив наборов: перемешивание для каждого студента не даёт поделиться ответом.
