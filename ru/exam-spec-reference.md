# Справочник по спецификации экзамена

Генератор экзаменов принимает **спецификацию**: документ JSON5, описывающий генеральную совокупность, а не набор данных. Данные каждого студента разыгрываются из этой совокупности с его собственным именем в качестве зерна, поэтому у всех получаются числа, принадлежащие только им, тогда как описанная вами структура – факторы, эффекты, пропуски – сохраняется для всех.

Одна и та же спецификация питает оба действия в этом разделе. **Экспортировать экзаменационную ссылку** превращает её в ссылку `?exam=`, которую открывают студенты; **Загрузить тестовые данные в приложение** разыгрывает один набор данных и загружает его прямо в DataSuite – так удобно проверять модуль на данных с известными свойствами.

> Эта страница – про набор данных. Про оцениваемые вопросы, которые едут поверх него, см. [справочник по вопросам экзамена](./exam-question-reference.md). Про то, что видит студент, – [прохождение экзамена](./taking-an-exam.md).

## Быстрый старт

```json5
{
	n: 200,
	factors: ["Physical", "Mental"],
	phi: { "Physical~Mental": 0.3 },
	defaults: { family: "beta", params: [2, 5], min: 0, max: 100, round: 0 },
	variables: {
		PF: { load: "Physical*0.80" },
		GH: { load: "Physical*0.55 + Mental*0.25" },
		MH: { load: "Mental*0.80" },
	},
	groups: {
		sex: { levels: ["F", "M"], effect: "Physical*-0.6" },
	},
}
```

Это полноценная спецификация: два коррелирующих латентных фактора, три опросниковые шкалы, измеряющие их по скошенной шкале 0–100, и различие между полами в 0.6 стандартного отклонения по фактору Physical.

JSON5 означает, что допустимы ключи без кавычек, комментарии и запятые в конце, – пишите как код, а не как конфигурационный файл.

Нажмите **Сформировать просмотр**, чтобы разыграть набор данных одного студента и считать с него реализованные числа, и **Пересоздать**, чтобы сменить зерно и увидеть, насколько далеко они гуляют от студента к студенту. **Вернуть пример** восстанавливает закомментированную стартовую спецификацию, в которой задействовано большинство описанных здесь полей.

## Два шаблона

Спецификация имеет одну из двух форм, и выбирает её то, какой ключ в ней есть.

| Шаблон | Признак | Форма | Чем анализировать |
|---|---|---|---|
| Факторная модель | `factors` + `variables` | Широкая – по строке на наблюдение, по столбцу на переменную | Всем: описательные статистики, корреляции, сравнение групп, факторный анализ, надёжность, регрессия, выживаемость |
| План эксперимента | блок `design` | Длинная – по строке на испытуемого × внутригрупповую ячейку, с идентификатором `subject` | [Сравнением групп](./comparison-analysis.md) – меж-, внутригрупповой и смешанный дисперсионный анализ и MANOVA |

Факторная модель – это психометрический движок: латентные переменные, на которые грузятся наблюдаемые индикаторы. Шаблон плана – экспериментальный: средние по ячейкам скрещённых факторов. Это альтернативы, а не слои: спецификация с блоком `design` полностью игнорирует ключи факторной модели.

## Поля, которые есть у любой спецификации

| Поле | Значение |
|---|---|
| `n` | Объём выборки, по умолчанию 200. В плане это число **испытуемых**, а число строк равно `n × число внутригрупповых ячеек` |
| `id` | Необязательное название экзамена, впечатываемое в строку происхождения выгруженного документа Word (только для факторной модели) |
| `exam` | Оцениваемые вопросы – см. [справочник по вопросам экзамена](./exam-question-reference.md) |

## Факторная модель

### Факторы и их корреляции

```json5
factors: ["Physical", "Mental"],
phi: { default: 0.3, "Physical~Mental": 0.45 },
paths: { "Physical->Mental": 0.4 },
```

- `factors` – имена латентных переменных. Столбцами они не выводятся никогда; выводятся только грузящиеся на них индикаторы.
- `phi` – корреляции факторов. Одно число применяется ко всем парам, либо задавайте пары по отдельности через `{ default: 0.3, "A~B": 0.45 }`. Если опустить, факторы некоррелированы.
- `paths` – направленные пути между факторами, превращающие модель измерения в [структурную](./structural-equation-modeling.md). `{ "Physical->Mental": 0.4 }` заставляет Mental регрессировать на Physical, так что предиктор, действующий на Physical, достигает Mental **косвенно**, – это настоящий набор данных с медиацией. Модель должна быть рекурсивной (ациклической); петля обратной связи отвергается с указанием имени. При наличии `paths` величина `phi` – это корреляция между *возмущениями*, а не между самими факторами.

> **Медиация – это произведение двух путей.** Косвенный эффект равен наклону предиктора на Physical, умноженному на путь Physical→Mental. Оба ослабляются измерением, поэтому реализованный коэффициент, который студент получит в [регрессии](./regression-analysis.md), меньше заданного вами – загрузите тестовые данные и постройте модель, чтобы увидеть величину, о которой вы на самом деле спрашиваете.

### Переменные

Каждая запись в `variables` – это один наблюдаемый индикатор. `load` – факторное выражение, задающее его нагрузку на каждый фактор, и кросс-нагрузки здесь полноправны.

```json5
defaults: { family: "beta", params: [2, 5], min: 0, max: 100, round: 0 },
variables: {
	PF: { load: "Physical*0.80" },
	GH: { load: "Physical*0.55 + Mental*0.25", family: "normal", params: [50, 10] },
	MH: { load: "Mental*0.80", params: [5, 2] },
},
```

`defaults` – распределение вывода, которое наследует каждая переменная; любое из `family`, `params`, `min`, `max`, `round` можно переопределить у отдельной переменной. Имена факторов внутри выражения `load` не могут содержать `+`, `−` или `*`.

> **Остаточная дисперсия выводится, а не задаётся.** Нагрузки индикатора фиксируют, какую его долю объясняют факторы; остальное – шум, вычисляемый как `1 − h²`. Нагрузки, забирающие почти всю дисперсию, оставляют индикатор, который почти детерминированно определяется факторами, – просмотр предупреждает, когда так происходит.

### Блоки пунктов

Шкале опросника из десятка пунктов не нужен десяток записей. `count` порождает блок, а **массив** наборов делает этот блок перемешиваемым.

```json5
variables: {
	WB: [
		{ count: 6, load: "Mental*0.65", jitter: 0.06 },
		{ count: 2, load: "Mental*-0.6" },
	],
},
```

- `count` – запись `WB: { count: 8, load: "Mental*0.7" }` создаёт `WB1` … `WB8`.
- **Массив наборов** перемешивается для каждого студента: пункты тасуются внутри блока, поэтому набор с **отрицательной** нагрузкой – обратный пункт – у каждого оказывается под своим именем. Ответ на вопрос «какие пункты обратные?» приходится тогда искать в таблице [надёжности](./reliability-analysis.md) при удалении пункта, и поделиться им нельзя.
- `jitter: 0.06` разводит нагрузки внутри набора на затравленную случайную величину, зафиксированную в момент написания, так что спецификация остаётся стабильной. `loadRange: [0.8, 0.4]` вместо этого задаёт линейный градиент по набору (только для однофакторных нагрузок).

> Обратный пункт – не какая-то особая настройка, это просто набор с отрицательной нагрузкой. Во всём остальном пункт самый обычный.

### Семейства распределений

Стандартизованное латентное значение каждой переменной прогоняется через обратную функцию распределения, чтобы получить своё маргинальное распределение. `params` задаётся позиционно для каждого семейства.

| Семейство | `params` | Примечания |
|---|---|---|
| `normal` | среднее, ст. отклонение | По умолчанию; опустите `params` для (0, 1) |
| `beta` | shape1, shape2 | Масштабируется в `[min, max]` – задавайте оба. Естественный выбор для ограниченного шкального балла |
| `gamma` | shape, rate | Положительное, скошенное вправо |
| `lognormal` | meanlog, sdlog | Положительное, с более тяжёлым правым хвостом |
| `poisson` | lambda | Счётные данные |
| `negbin` | среднее, size | Счётные данные со сверхдисперсией |
| `zip` | lambda, доля нулей | Пуассон с избытком нулей |
| `zinb` | среднее, size, доля нулей | Отрицательное биномиальное с избытком нулей |
| `ordinal` | пороги… | Точки разреза на латентной шкале → коды Ликерта 1, 2, 3, … |
| `skew-normal` | положение, масштаб, форма | Настоящая асимметрия без усечения |
| `t` | df, положение, масштаб | Тяжёлые хвосты; положение и масштаб необязательны |
| `mixture` | вес, среднее, ст. отклонение × ≥ 2 | Многомодальное – по тройке на компоненту |
| `binomial` | size, вероятность | `size: 1` – это исход 0/1 для логистической регрессии |
| `bernoulli` | вероятность | Сахар для `binomial(1, prob)` |
| `exponential` | rate | Время до события (без памяти) |
| `weibull` | shape, scale | Время до события |
| `loglogistic` | shape, scale | Время до события |
| `gompertz` | shape, rate | Время до события (растущий риск) |

`min` и `max` усекают вывод, а `round` задаёт число знаков после запятой; применяются они после семейства – кроме `beta`, которое и так попадает в диапазон, и `ordinal`, чьи коды категориальны. Именно усечение накапливает массу у потолка или пола, о чём просмотр сообщает как `%=max`.

> **Ненормальные маргинальные распределения искажают корреляции.** Латентная структура – ровно та, которую вы задали, но прогон её через нелинейное маргинальное преобразование сдвигает корреляцию Пирсона от заданного значения – сильнее всего у бинарных исходов, где у коэффициента φ потолок ниже 1. Ранговая структура при этом сохраняется. Это главная причина, по которой ключ ответов – реализованные числа просмотра, а не спецификация.

### Метки

`labels` называет уровни исхода семейства `binomial`, превращая числовой столбец в категориальный.

```json5
Remission: { load: "Mental*0.70", family: "bernoulli", params: [0.4], labels: ["No", "Yes"] },
```

Опустите их, чтобы получить обычный столбец 0/1, – именно это и нужно, если студент должен построить на нём логистическую регрессию. По одной метке на уровень, поэтому `size: 1` требует двух.

### Пропущенные данные

`missing` пробивает дыры в переменной или предикторе, затравливаясь именем студента, как и всё остальное.

```json5
missing: 0.2,
missing: { mechanism: "mar", rate: 0.12, on: "age", slope: 0.8 },
```

- Просто число – это доля пропусков по механизму MCAR.
- `mechanism: "mar"` ставит пропуски в зависимость от **другого** столбца, названного в `on`; `"mnar"` – от собственного значения переменной. `slope` задаёт силу этой зависимости в логит-шкале.
- `rate` – базовая доля, а не точная реализованная, как только `slope` отличен от нуля. Реализованный процент пропусков сообщает просмотр.

Какие наблюдения в итоге участвуют в анализе, зависит уже от [настройки пропущенных данных](./settings.md#пропущенные-данные) у студента, так что спецификация с пропусками заодно проверяет, заметил ли он их.

### Исходы выживаемости

`censor` превращает переменную в исход «время до события», выводя два столбца: `<имя>` (наблюдаемое время) и `<имя>_event` (статус: `0` – цензурировано, `1` – событие, `2…` – каждая конкурирующая причина). Нужно семейство выживаемости.

```json5
TimeToRelapse: { load: "Mental*0.6", family: "weibull", params: [1.3, 40], censor: { mechanism: "random", rate: 0.02 } },
```

| `mechanism` | Дополнительные поля | Что делает |
|---|---|---|
| `random` | `rate` | С событием конкурирует экспоненциальное время цензурирования |
| `fixed` | `at` | Административная отсечка – все, кто к этому моменту ещё под риском, цензурируются |
| `type2` | `events` | Остановка после k событий; все после k-го цензурируются |
| `competing` | `risks`, необязательное `at` | Независимые конкурирующие причины, у каждой своё семейство и параметры; побеждает ближайшая |

Ковариаты масштабируют время (модель AFT, а не пропорциональных рисков Кокса), поэтому реализованное отношение рисков – это то, что студент получит в [анализе времени до события](./time-to-event-analysis.md). Просмотр сообщает реализованную долю событий, медианное время и долю цензурированных.

### Категориальные группы

```json5
groups: {
	condition: { levels: ["Healthy", "Chronic"], effect: "Physical*-0.8 + Mental*-0.3", spread: [1, 1.5] },
	sex: { levels: ["F", "M"] },
},
groupPhi: { "condition~sex": 0.35 },
```

- `levels` – метки уровней, выводимые категориальным столбцом.
- `effect` – факторное выражение, сдвигающее средние факторов между соседними уровнями в единицах стандартного отклонения фактора. Для двух уровней это прямо d Коэна; для большего числа – сдвиг на шаг при центрированных уровнях.
- `spread` – по множителю на уровень, масштабирующему **дисперсию** этого уровня и только её. Группа может различаться разбросом, не различаясь средним, – именно это делает осмысленным вопрос «Уэлч или Стьюдент».
- `groupPhi` – связывает категориальные переменные между собой, так что критерий χ² независимости между двумя из них не оказывается пустым по построению. Сокращённая запись та же, что у `phi`. Задаётся латентная корреляция за категориальными переменными; ключ ответов – реализованные χ² и V Крамера.

### Непрерывные предикторы

Предикторы – это ковариаты, сдвигающие средние факторов, непрерывный аналог группового `effect`; каждый из них выводится ещё и собственным столбцом.

```json5
predictors: {
	age:    { family: "normal", params: [40, 12], effect: "Physical*-0.5" },
	visits: { family: "negbin", params: [4, 2],   effect: "Physical*-0.3" },
},
predictorPhi: { "age~visits": 0.3 },
interactions: { "age:condition": "Physical*-0.3" },
```

- `effect` – наклон на латентный фактор в единицах стандартного отклонения.
- Предикторы **не** наследуют `defaults` – бета-распределение 0–100 по умолчанию превратило бы «возраст» в бессмыслицу, – поэтому каждый несёт своё `family` и `params`, по умолчанию нормальное(0, 1).
- `predictorPhi` – корреляции между предикторами, сокращённая запись та же, что у `phi`. Отсюда берётся мультиколлинеарность.
- `interactions` – произведения. Ключ соединяет имена двух предикторов или групп через `:`, а значение – наклон модерации на фактор. Допустим любой порядок взаимодействия.

> **Наклон действует на фактор, а не на индикатор.** Поэтому регрессия одного индикатора на предиктор восстанавливает примерно `нагрузка × наклон`, ослабленное измерением. Если нужна регрессия, коэффициент которой окажется ровно там, куда вы его поставили, дайте исходу собственный фактор с одним индикатором и нагрузкой около 1.

### Кластеризация

Наблюдения вложены в кластеры – пациенты в клиниках, ученики в классах – со случайными свободными членами по факторам и, при желании, со случайным наклоном.

```json5
clustering: {
	cluster: "clinic", nClusters: 12,
	intercept: "Physical*0.4 + Mental*0.3",
	slope: { predictor: "age", factor: "Physical", sd: 0.15, corr: 0.3 },
	sizes: [30, 20, 20, 10],
},
```

- `cluster` / `nClusters` – выводимый столбец идентификатора и число разыгрываемых кластеров. `sizes` задаёт размеры явно вместо равного деления.
- `intercept` – стандартное отклонение случайного свободного члена кластера по каждому фактору. Именно он создаёт внутрикластерную корреляцию; реализованный ICC сообщает просмотр.
- `slope` – необязательный случайный наклон одного предиктора для одного фактора, со своим `sd` и корреляцией `corr` со свободным членом.

Кластер плюс предиктор времени плюс случайный наклон – это модель роста в длинном формате.

### Временные ряды

Блок `timeseries` заменяет независимое одинаково распределённое возмущение фактора процессом SARIMA, идущим по временному индексу.

```json5
timeseries: {
	time: "week", order: [1, 1, 1], ar: [0.6], ma: [-0.3],
	seasonal: [1, 0, 0], sar: [0.4], period: 12,
	unit: "store", units: 24,
	start: "2020-01-06", step: "week",
},
```

- `time` – имя выводимого столбца времени. `order` – это `[p, d, q]`, а `seasonal` – `[P, D, Q]` с периодом `period`, по коэффициенту на порядок в `ar` / `ma` / `sar` / `sma`.
- `unit` + `units` превращают ряд в панель и выводят столбец идентификатора единицы (`sizes` задаёт длины по единицам); задавайте оба или ни одного. Опустите их для одиночного ряда Бокса–Дженкинса или чтобы унаследовать группировку от `clustering`.
- `start` (дата `YYYY-MM-DD`) + `step` (`day`, `week`, `month`, `quarter` или `year`) выводят временной индекс настоящими датами, а не целыми числами. Задавайте оба или ни одного. Это важнее, чем кажется: [анализ временных рядов](./time-series-analysis.md) считывает сезонный период с шага столбца и может сделать это только для столбца, который разбирается как дата, – голый целочисленный индекс всегда даёт частоту 1.

Ряд с разностями (`d` или `D` больше нуля) нестационарен и не имеет фиксированной дисперсии, поэтому держите его индикаторы на маргинальном распределении `normal`. Возмущение каждого фактора ведёт одна общая структура, а ключ ответов – реализованная автокорреляция первого порядка в просмотре; на коротких панелях она смещена вниз, и это свойство оценки на малой выборке, а не изъян генератора.

### Явная матрица нагрузок

`loadings` верхнего уровня принимает обычную матрицу строки × факторы и полностью обходит выражения `load`. Она нужна для обратной загрузки и для вставки матрицы из статьи; с блоками пунктов её сочетать нельзя, поскольку сопоставить с ними число строк невозможно.

## Экспериментальные планы

Задайте блок `design` вместо `factors` / `variables`, чтобы получить данные в длинном формате для дисперсионного анализа и MANOVA.

```json5
{
	n: 60,
	design: {
		between: { group: ["control", "treat"] },
		within: { time: ["pre", "mid", "post"] },
		outcomes: {
			anxiety: { mean: 50, sd: 10, effect: "group*0.6 + time*0.4 + group:time*0.5" },
			mood:    { mean: 20, sd: 4,  effect: "time*-0.3" },
		},
		cov: { type: "ar1", rho: 0.5 },
		outcomeCov: { "anxiety~mood": -0.4 },
	},
}
```

| Поле | Значение |
|---|---|
| `between` | Межгрупповые факторы; каждому испытуемому назначается одна ячейка, сбалансированно по всему скрещиванию |
| `within` | Внутригрупповые факторы (повторные измерения), полностью скрещённые внутри каждого испытуемого – по строке на ячейку плюс столбец идентификатора испытуемого |
| `outcomes` | Зависимые переменные, по записи на каждую |
| `cov` | Внутрииспытуемая ковариация Σ_W |
| `outcomeCov` | Корреляция между исходами для MANOVA с несколькими зависимыми переменными, сокращённая запись та же, что у `phi`; если опущена – исходы независимы |
| `subject` | Имя столбца с идентификатором испытуемого, по умолчанию `subject`, выводится только при наличии внутригрупповых факторов |

Плану нужен хотя бы один фактор `between` или `within` и хотя бы один исход. Чисто внутригрупповой вариант допустим.

### Исходы

Исход семейства `normal` принимает `mean` и `sd` плюс либо выражение `effect`, либо таблицу `cells`. Любое другое `family` принимает `params` и проходит через то же преобразование NORTA, что и факторная модель, поэтому `mean`, `sd` и `cells` доступны только для нормального.

- `effect` – выражение в единицах d Коэна над именами межгрупповых и внутригрупповых факторов, где `:` образует член взаимодействия: `"group*0.6 + time*0.4 + group:time*0.5"`. Это экономный вариант по умолчанию.
- `cells` – явная таблица средних по ячейкам с ключами из склеенных запятой меток уровней, для узора, который не описывается линейным выражением: `{ "control,pre": 48, "control,post": 52 }`.
- `missing` и `labels` работают на каждом исходе ровно так же, как на переменной факторной модели, с той разницей, что ссылка `on` при механизме `mar` называет другой **исход**.

> **Межгрупповые эффекты здесь попадают точно.** Средние по ячейкам детерминированы, поэтому заданное d = 0.6 и есть d = 0.6 в генеральной совокупности – нет нагрузки, которая бы его ослабила. Это единственное место в генераторе, где заданное число и популяционное – одно и то же. Ненормальные маргинальные распределения и критерии, зависящие от внутригрупповой корреляции, всё равно реализуются от него.

### Внутрииспытуемая ковариация

`cov` – это одна матрица с тремя способами построения:

| Форма | Значение |
|---|---|
| `{ type: "cs", rho: 0.6 }` | Составная симметрия – одна корреляция между каждой парой ячеек. По умолчанию, при ρ 0.5 |
| `{ type: "ar1", rho: 0.5 }` | ρ^\|i−j\|, так что соседние моменты времени коррелируют сильнее далёких. Нужен единственный упорядоченный внутригрупповой фактор |
| `{ "pre~post": 0.4 }` | Неструктурированная, с ключами по меткам внутригрупповых ячеек |

Она применяется к нормальной латентной переменной, поэтому для нормальных исходов точна, а для остальных искажается.

Анализируйте результат [модулем сравнения групп](./comparison-analysis.md): межгрупповые факторы отображаются в группирующую переменную, внутригрупповые – в условие, а столбец испытуемого – в идентификатор испытуемого. Это родная для модуля раскладка, поэтому ничего сшивать не нужно.

## Реализованное, а не заданное

Каждое число в спецификации описывает генеральную совокупность. Студент анализирует одну выборку из неё, поэтому реализованная корреляция 0.42 при заданной 0.45 – не ошибка, а та самая выборочная изменчивость, которая делает набор данных каждого студента его собственным. Два следствия стоит усвоить.

**Ключ ответов – просмотр, а не спецификация.** Везде, где между написанным вами и появившимся в столбце стоит нелинейное маргинальное преобразование, модель измерения или преобразование NORTA, значение имеет реализованная величина. Постройте просмотр и считайте её.

**Значимость возникает сама.** Вы задаёте размеры эффектов; преодолеет ли t-критерий конкретного студента порог α – честное следствие его выборки. Это достоинство: фразой «это переменные 1 и 3» поделиться нельзя, – но это же значит, что эффект, припаркованный у порога, превращает вопрос в подбрасывание монеты. Задавайте эффекты с хорошим запасом от нуля, если только изменчивость и не является целью.

## Защитные проверки

Построитель проверяет спецификацию до генерации и сообщает о проблеме там, где с ней можно что-то сделать:

- Корреляционная матрица (`phi`, `predictorPhi`, `groupPhi`, `outcomeCov`), не являющаяся положительно определённой, отвергается с указанием имени до генерации, а не всплывает сырой ошибкой решателя посреди розыгрыша.
- Просмотр предупреждает, когда нагрузки индикатора почти не оставляют ему остаточной дисперсии, из-за чего он становится почти детерминированной функцией факторов. Понизьте нагрузки, если это не было задумано.
- Неизвестные имена факторов, некорректные выражения мини-языков, неверное число параметров семейства и цикл в блоке `paths` – обо всём этом сообщается с указанием записи, вызвавшей проблему.

## Советы

**Пишите вопросы под те данные, которые действительно разыграны.** Напишите спецификацию, постройте просмотр, затем напишите блок `exam` и нажмите **Вычислить ключ ответов**. Вопрос хорош ровно настолько, насколько хорош реализованный набор данных под ним: вопрос-множество, ответом на который при каждом пересоздании оказывается вся область, говорит вам, что эффекты слишком велики.

**По одной ссылке на блок заданий.** Ссылка несёт один набор данных. Вопросам, которым нужна другая структура – повторные измерения, другая группирующая переменная, другой инструмент, – место в собственной ссылке с собственной спецификацией.

**Используйте `id`, чтобы подписать экзамен.** Он попадает в строку происхождения выгруженного документа, и именно она говорит вам, к какому заданию относится присланный файл.

**Пересоздавайте перед экспортом.** Картина значимых результатов должна меняться от студента к студенту. Если она не меняется никогда, у всех студентов одни и те же ответы, и защита от списывания исчезла.

**Тестовые данные – инструмент отладки.** Всё, о чём не сообщает просмотр – реализованное взаимодействие, косвенный эффект, ICC на конкретном индикаторе, – находится в одном нажатии **Загрузить тестовые данные в приложение** от того, чтобы быть измеренным в самом приложении.

## Что выбрать

**Факторная модель или план?** Если вопрос про измерение – надёжность, факторная структура, корреляции между шкалами, – это факторная модель. Если про эксперимент с условиями и ячейками – это план. Яснее всего разделяют повторные измерения: шаблон плана выводит длинный формат, который модуль сравнения групп читает изначально, тогда как факторный путь вывел бы широкие столбцы, которые студенту пришлось бы сначала сшивать.

**`effect` или `cells`?** Выражение `effect` короче и говорит то, что вы имеете в виду, – главные эффекты и взаимодействия в единицах d. Беритесь за `cells`, только когда узор нелинеен: перекрёст, выход на плато, одна выбивающаяся ячейка.

**`groups` или `predictors`?** Группа категориальна и выводит уровни; предиктор непрерывен и выводит число. Оба сдвигают средние факторов, поэтому выбор сводится к тому, какой анализ вы хотите заставить выполнить студента – сравнение групп или регрессию.

**Блок пунктов или перечисление?** Перечисляйте, пока каждый пункт содержательно отличается. Переходите на блок, как только они становятся вариациями одной нагрузки, и берите массив наборов, как только в игру вступают обратные пункты: перемешивание для каждого студента – это то, что не даёт поделиться ответом.
