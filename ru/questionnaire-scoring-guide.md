# Руководство по подсчёту баллов по опросникам

Ниже на трёх примерах из практики, от простого к сложному, показано, как подсчитать баллы по опроснику. Все примеры построены на правилах [преобразования данных](./data-transformation.md), поэтому, если вы ещё не работали с этим разделом, начните с его страницы.

Отправная точка у всех трёх одна: таблица (например, выгруженная из Google Forms), где строка — респондент, а столбец — пункт опросника. Ответы в ней записаны текстом («Полностью согласен») или уже числами, но для анализа в любом случае нужны баллы по шкалам.

## Пример 1: PHQ-9 (простая сумма)

[PHQ-9](https://en.wikipedia.org/wiki/PHQ-9) — опросник из 9 пунктов для скрининга депрессии. В каждом пункте респондент отмечает, как часто за последние две недели его беспокоил тот или иной симптом. Обратных пунктов нет, так что ответы достаточно перекодировать и сложить.

**Варианты ответов:** «Ни разу» (0), «Несколько дней» (1), «Более недели» (2), «Почти каждый день» (3). Суммарный балл лежит в пределах 0–27. {#-}

### Шаг 1: перекодирование текста в числа

Если ответы уже записаны числами от 0 до 3, пропустите этот шаг.

1. Откройте **Преобразование данных** и нажмите **+ Перекодировка значений**
2. На панели входных переменных выберите все 9 пунктов PHQ-9
3. Редактор сам перечислит текстовые значения, которые встречаются в данных. Сопоставьте им числа:

| Старое значение | Новое значение |
|---|---|
| Ни разу | 0 |
| Несколько дней | 1 |
| Более недели | 2 |
| Почти каждый день | 3 |

4. В параметрах вывода выберите **Заменить исходные значения**: текст больше не понадобится
5. Назовите правило (например, «PHQ-9, перекодирование») и нажмите **Сохранить правило**

### Шаг 2: вычисление суммарного балла

1. Нажмите **+ Формула**
2. Выберите входными переменными те же 9 пунктов
3. Введите формулу:

```
sum(v1:v9)
```

4. В параметрах вывода выберите **Создать новые переменные** и задайте имя `PHQ9_Total`
5. Сохраните правило

Готово: в данных появился столбец `PHQ9_Total` с баллами от 0 до 27.

## Пример 2: шкала самооценки Розенберга (прямые и обратные пункты)

[Шкала самооценки Розенберга](https://en.wikipedia.org/wiki/Rosenberg_self-esteem_scale) состоит из 10 пунктов с четырёхбалльной шкалой ответов. Пункты 3, 5, 8, 9 и 10 сформулированы негативно, и перед суммированием их нужно перевернуть.

**Варианты ответов:** «Полностью согласен» (3), «Согласен» (2), «Не согласен» (1), «Совершенно не согласен» (0). Суммарный балл лежит в пределах 0–30. {#-}

### Вариант А: переворачивание при подсчёте (рекомендуется)

В этом варианте исходные значения пунктов не меняются, и отдельный шаг перекодирования не нужен. Пункт переворачивается прямо в формуле по схеме `(макс - пункт)`, где макс для шкалы 0–3 равен 3:

1. Нажмите **+ Формула**
2. Выберите входными переменными все 10 пунктов шкалы Розенберга, по порядку
3. Введите формулу:

```
v1 + v2 + (3-v3) + v4 + (3-v5) + v6 + v7 + (3-v8) + (3-v9) + (3-v10)
```

4. Создайте новую переменную `RSE_Total`
5. Сохраните правило

Обратные пункты (v3, v5, v8, v9, v10) переворачиваются прямо в формуле: ответ 0 превращается в 3, 1 — в 2 и так далее. Исходные данные не меняются, поэтому отдельные пункты потом легко проверить. Именно такие данные нужны и [IRT-анализу](./irt-analysis.md#обратные-пункты) тех же пунктов: модуль сам переворачивает обратные пункты, проверке на небрежные ответы нужны данные в том виде, в каком их дали респонденты, а обнаружение обратных пунктов не распознаёт переворачивания, сделанного заранее.

### Вариант Б: перекодирование, затем суммирование

Если перевёрнутые значения должны храниться в данных явно:

1. **+ Стандартизация** — выберите только 5 обратных пунктов (3, 5, 8, 9, 10), метод **Обратное кодирование** и диапазон шкалы: **Мин** 0, **Макс** 3. Выберите **Создать новые переменные** и задайте префикс, например `r`: перевёрнутые копии появятся рядом с исходными столбцами. (Вручную то же самое делается через **+ Перекодировка значений** с соответствием 0→3, 1→2, 2→1, 3→0.)
2. **+ Формула** — выберите 5 прямых пунктов и 5 перевёрнутых копий. Формула: `sum(v1:v10)`. Создайте новую переменную `RSE_Total`.

Оба варианта дают одинаковый результат. Вариант А компактнее, а в варианте Б перевёрнутые значения видны в таблице данных. Если пункты могут понадобиться для IRT-анализа, не выбирайте **Заменить исходные значения** (см. совет [«По возможности сохраняйте исходные данные»](#b-keep-originals-intact-when-possible)).

## Пример 3: TIPI — Ten-Item Personality Inventory (несколько субшкал)

[TIPI](https://gosling.psy.utexas.edu/scales-weve-developed/ten-item-personality-measure-tipi/) измеряет черты «Большой пятёрки» всего десятью пунктами: по два на черту, один прямой и один обратный. Ответы даются по шкале от 1 («Совершенно не согласен») до 7 («Полностью согласен»), а балл по субшкале — это **среднее** двух её пунктов.

Структура опросника:

| Черта | Прямой пункт | Обратный пункт |
|---|---|---|
| Экстраверсия | 1. Экстравертированный, полный энтузиазма | 6. Сдержанный, тихий |
| Доброжелательность | 7. Отзывчивый, тёплый | 2. Критичный, склонный к спорам |
| Добросовестность | 3. Надёжный, дисциплинированный | 8. Неорганизованный, беспечный |
| Эмоциональная стабильность | 9. Спокойный, эмоционально устойчивый | 4. Тревожный, легко расстраивающийся |
| Открытость опыту | 5. Открытый новому, сложный | 10. Консервативный, не склонный к творчеству |

### Подсчёт с помощью многопеременной формулы

Это как раз случай для синтаксиса `@`: все пять субшкал вычисляются одним правилом.

1. Нажмите **+ Формула**
2. Выберите входными переменными все 10 пунктов TIPI по порядку номеров (1–10)
3. Введите формулу:

```
@Extraversion = (v1 + (8-v6)) / 2
@Agreeableness = ((8-v2) + v7) / 2
@Conscientiousness = (v3 + (8-v8)) / 2
@EmotionalStability = ((8-v4) + v9) / 2
@Openness = (v5 + (8-v10)) / 2
```

4. Сохраните правило (с объявлениями `@` параметры вывода задаются автоматически)

Здесь пункты переворачиваются по схеме `(8 - пункт)`: шкала идёт от 1 до 7, так что макс + 1 = 8. Балл по субшкале тоже лежит в пределах от 1 до 7.

> **Почему `(8 - v)`, а не `(7 - v)`?** Перевёрнутый балл всегда равен `(макс + мин) - значение`. Для шкалы 1–7 это `(7 + 1) - v = 8 - v`, для шкалы 0–3 (как в примере со шкалой Розенберга) — `(3 + 0) - v = 3 - v`. Так диапазон шкалы остаётся прежним.

## Общие советы

- **Проверяйте диапазон шкалы.** От него зависит формула переворачивания: `(макс + мин) - значение`. Для шкалы Лайкерта 1–5 это `6 - v`, для 0–4 — `4 - v`, для 1–7 — `8 - v`. Все функции и синтаксис формул описаны в [справочнике формул](./formula-reference.md). [Обратное кодирование в правиле стандартизации](./data-transformation.md#стандартизация) вычисляет ту же формулу по заданному диапазону шкалы и одним правилом переворачивает любое число пунктов.
- **По возможности сохраняйте исходные данные.** Если переворачивать пункты прямо в формуле (вариант А), ответы по отдельным пунктам всегда можно проверить, не гадая, какие значения были перекодированы. Если по этим пунктам запланирован или возможен IRT-анализ, исходные значения сохраняйте обязательно: [модуль IRT](./irt-analysis.md#обратные-пункты) сам переворачивает обратные пункты, проверке на небрежные ответы нужны ответы в исходном виде, а обнаружение обратных пунктов не распознаёт переворачивания, сделанного в данных. [Анализ надёжности](./reliability-analysis.md#обратные-пункты) тоже переворачивает пункты сам и только на время анализа.
- **Давайте переменным понятные имена.** Описательные имена вроде `PHQ9_Total`, `RSE_Total`, `Extraversion` потом встретятся во всех результатах анализа.
- **Правила применяются по порядку.** Если первое правило перекодирует текст в числа, формула во втором правиле получит уже числа. Промежуточный результат можно в любой момент проверить в [предпросмотре данных](./getting-started.md#просмотр-данных).
- **Сохраняйте файл проекта.** Правила преобразования хранятся внутри файла проекта (.json), и при повторном открытии проекта все правила восстанавливаются. Правила можно также сохранить в [библиотеке правил](./data-transformation.md#библиотека-правил), чтобы пользоваться ими в других проектах.
