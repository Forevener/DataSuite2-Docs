# Справочник по вопросам экзамена

Экзамен — это блок `exam` в спецификации генератора. В блоке перечислены вопросы. Для каждого из них задано, что вводит студент и как по **его** набору данных вычисляется правильный ответ. Данные генерируются по имени студента, поэтому ключ ответов не записывается заранее, а вычисляется для каждого студента отдельно: вы составляете вопрос, а не ответ.

Вопросы компилируются при экспорте ссылки, поэтому опечатка в имени переменной или неизвестный метод обнаружатся в редакторе, а не у студента.

> Эта страница посвящена вопросам. Сам набор данных (факторы, переменные, группы, распределения, планы) описан в [справочнике по спецификации экзамена](./exam-spec-reference.md), а то, что видит студент, — на странице [Прохождение экзамена](./taking-an-exam.md).

## Быстрый старт

```json5
exam: {
	gate: "warn", threshold: 1,
	questions: [
		{
			id: "q1",
			text: "Какие шкалы различаются между мужчинами и женщинами? (Манна — Уитни, α = 0.05)",
			answer: { type: "set", over: "vars('PF','GH','MH')" },
			truth: { over: "vars('PF','GH','MH')", where: "compare2(sex, $v, 'mannWhitneyU').p < 0.05" },
		},
	],
}
```

Вот и всё устройство вопроса: `answer` описывает элемент ввода, а `truth` — вычисление. Перед экспортом нажмите **Вычислить ключ ответов** в генераторе экзаменов: приложение создаст пример набора данных и вычислит на нём все эталоны.

## Блок exam

| Поле | Значение |
|---|---|
| `gate` | Что происходит с экспортом в Word, если результат ниже порога: `"export"` блокирует экспорт, `"warn"` запрашивает подтверждение, `"none"` ничего не меняет |
| `threshold` | Доля оцениваемых вопросов, на которые нужно ответить верно, по умолчанию `1` (все) |
| `questions` | Список вопросов по порядку: в этом порядке их видит студент, по нему же разрешаются ссылки `@qN` |

Вопросы-выборы и вопросы для письменного ответа в счёт не входят, поэтому `threshold: 1` означает все *оцениваемые* вопросы.

## Вопрос

| Поле | Обязательно | Значение |
|---|---|---|
| `id` | да | Имя, по которому на вопрос ссылаются следующие вопросы (`@q1`). Должно быть уникальным |
| `text` | да | Показывается студенту дословно и **не переводится**: пишите на языке, на котором преподаёте |
| `answer` | да | Элемент ввода и способ сверки ответа |
| `truth` | кроме `pick` / `prose` | Выражение, вычисляющее правильный ответ |
| `scope` | нет | Ограничивает эталон частью строк |

Метод задаётся текстом вопроса. Спросить студента, *какой критерий уместен*, язык вопросов не позволяет: критерий, одно- или двустороннюю проверку, апостериорный метод и α вы указываете в формулировке, а задача студента — правильно выполнить анализ.

## Типы ответов

| `type` | Элемент ввода | Как сверяется |
|---|---|---|
| `scalar` | текстовое поле | По значению в том виде, в каком его **показывает** приложение при настройках точности самого студента |
| `value` | выпадающий список | Точное совпадение |
| `set` | список флажков | Точное совпадение множеств, оценивается целиком |
| `table` | сетка, по строке на элемент | По ячейкам: вопрос засчитан, когда верны все ячейки |
| `pick` | выпадающий список или флажки | Не оценивается: это ввод, на который опираются следующие вопросы |
| `prose` | строка-напоминание | Не оценивается: ответ вы читаете в документе |

### `scalar`

```json5
answer: { type: "scalar" }                    // сверяется по отображаемому значению
answer: { type: "scalar", tol: 0 }            // точно — для частот
answer: { type: "scalar", kind: "pvalue" }    // формат p-значения и правило нижней границы
```

- `tol` — допуск: засчитывается любое значение в пределах ± этой величины от эталона, а `tol: 0` означает точное совпадение. Без `tol` эталон форматируется так же, как числа в выводе приложения, и сравнивается как текст. На этом и держится правило «вводите то, что показывает экран».
- `kind` — категория точности, по которой форматируется значение: `descriptive` (по умолчанию), `statistic` или `pvalue`. Ячейка `pvalue` засчитывает и любое значение не выше нижней границы отображения, ведь там экран показывает только `< 0.001`.

### `value`

```json5
answer: { type: "value", from: "levels(sex)" }
answer: { type: "value", from: ["да", "нет"] }
```

`from` — это [область](#области). Обычный массив задаёт список ответов буквально.

### `set`

```json5
answer: { type: "set", over: "numericVars" },
truth:  { over: "numericVars", where: "compare2(sex, $v, 'mannWhitneyU').p < 0.05" }
```

Эталон записывается как `{ over, where }`: `$v` по очереди принимает значение каждого элемента, и ответом служат элементы, для которых выполняется `where`. Множество оценивается целиком, без отметок за отдельные элементы. Поэтому, ошибившись, студент возвращается к собственной таблице результатов, а не подбирает ответ по одному флажку.

Элементы области уходят в модуль анализа одним пакетом, за один запуск. Этого требует сам текст вопроса («выберите все эти переменные и запустите анализ один раз»), и только так поправка на множественные сравнения даёт верный результат.

### `table`

```json5
answer: {
	type: "table",
	rows: "vars('O','C','E','A','N')",
	cols: {
		r: { type: "scalar", kind: "statistic" },
		p: { type: "scalar", kind: "pvalue" },
		significant: { type: "value", from: ["да", "нет"] },
	},
},
truth: {
	r: "cor(age, $row, 'pearson').r",
	p: "cor(age, $row, 'pearson').p",
	significant: "if(cor(age, $row, 'pearson').p < 0.05, 'да', 'нет')",
}
```

Строк в таблице столько, сколько элементов в `rows`, а в каждом столбце стоит ячейка своего типа, `scalar` или `value`. Эталон состоит из выражений по одному на столбец, и `$row` в них принимает значение элемента строки. Выражение нужно для каждого ключа столбца.

### `pick`

```json5
answer: { type: "pick", from: "@q2" }                      // один из прежних ответов студента
answer: { type: "pick", from: "items('A')", n: "any" }     // любое их число
answer: { type: "pick", from: "numericVars", n: 3 }        // ровно три
```

У выбора **нет эталона**, и он никогда не оценивается. Он нужен, чтобы следующие вопросы работали с выбором самого студента: *выберите одну из шкал, которые вы только что перечислили*, а затем *у какого пола баллы по ней выше?* Если несколько выборов берут варианты из одной области, `distinct: true` запрещает повторы.

### `prose`

```json5
answer: { type: "prose" }
```

Ни элемента ввода, ни эталона — только строка, которая напоминает студенту описать результат словами. В экспортированном листе ответов она помечена как неоцениваемая.

## Эталонные выражения

Эталон — это небольшое выражение, записанное строкой. В нём допустимы:

- числа, `'строки в кавычках'` и имена столбцов без кавычек (`age`, `PF`, `sex`)
- `$v` (текущий элемент множества) и `$row` (текущая строка таблицы)
- `@qN` — ответ студента на один из предыдущих вопросов
- вызовы примитивов с позиционными аргументами — `compare2(sex, PF, 'mannWhitneyU')`
- обращение к полю (`.p`, `.r`, `.alpha`) и индексация по элементу (`.itemTotal[$v]`, `[$v]`)
- сравнения `== != < <= > >=`, `and` / `or` / `not` и `if(условие, a, b)`

Ни переменных, ни циклов, ни собственных функций в языке нет: весь язык — это [каталог примитивов](#каталог-примитивов).

Эталон может вернуть **список допустимых ответов**, и тогда засчитывается любой из них. Так учитываются совпадения: `mode` возвращает все значения с одинаковой наибольшей частотой, а функции поиска крайнего уровня — все уровни с одинаковым крайним значением, поэтому собственное правило для совпадений не нужно.

## Области

Область — это то, по чему пробегает `set`, из чего предлагают варианты `value` и `pick` и что образует строки `table`. Область задаётся выражением, так же как эталон:

| Область | Что даёт |
|---|---|
| `vars('PF','GH','MH')` | перечисленные поимённо столбцы |
| `items('SF')` | все столбцы блока пунктов из спецификации |
| `numericVars` | все числовые столбцы |
| `allVars` | все столбцы |
| `outcomes` | столбцы исходов из спецификации `design` |
| `levels(sex)` | уровни группирующего фактора или фактора повторных измерений |
| `pairs(levels(site))` | неупорядоченные пары уровней из списка — для вопросов об апостериорных сравнениях |
| `@q2` | ответ студента на предыдущий вопрос типа `set` или `pick` |
| `['да', 'нет']` | значения, заданные буквально |

> **Запомните эту ловушку:** **массив** JSON5 — это всегда список значений, а не список столбцов. `rows: ['PF','GH']` даст две строки с подписями `PF` и `GH`, а `rows: "vars('PF','GH')"` — два столбца. Если нужны столбцы, пишите выражение.

## Ссылки и ограничение строк

`@qN` ссылается только на один из предыдущих вопросов: ссылку вперёд или на несуществующий вопрос компилятор отвергает. Внутри эталона ссылка превращается в значение: в столбец, если студент выбирал переменную, в уровень, если он выбирал уровень, и в множество, если ответом было множество.

```json5
{ id: "q3", text: "У какого пола она выше?",
  answer: { type: "value", from: "levels(sex)" },
  truth: "argmax_level(sex, @q2, 'median')" }
```

Вопрос, *область* которого ссылается на предыдущий ответ, показывает строку ожидания, пока на тот вопрос нет ответа. Вопрос, эталон которого лишь *использует* предыдущий ответ, показывается и принимает ответ как обычно, и только его проверка сообщает об ожидании.

`scope` ограничивает строки для вычисления эталона и в точности повторяет диалог **Наблюдения**, так что в тексте вопроса можно назвать тот самый фильтр, который студенту нужно выставить:

```json5
scope: { country: ['Франция', 'Испания'] }   // категориальный: эти уровни
scope: { country: '@q4' }                    // уровни, выбранные студентом
scope: { age: [30, null] }                // числовой диапазон, null — открытая граница
scope: { age: { min: 30, max: 60 } }      // то же самое, развёрнуто
```

## Каталог примитивов

Все примитивы работают с неизменной копией сгенерированного набора данных студента. Столбец **Где** показывает, вычисляется ли примитив в браузере или передаётся модулю анализа, к которому он относится. Примитивы на R требуют обращения к движку, поэтому вопрос на их основе проверяется секунду-другую.

### Подсчёт

| Примитив | Где | Возвращает |
|---|---|---|
| `nrows()` | браузер | Число строк в пределах ограничения |
| `count(predicate)` | браузер | Число строк, для которых условие выполняется, например `count(sex == 'female')` |
| `percent(predicate)` | браузер | Процент от **всех** строк |
| `validPercent(predicate)` | браузер | Процент от строк без пропусков в переменных условия |
| `prop(predicate)` | браузер | `validPercent` в виде доли |
| `freq(variable)` | браузер | Таблица частот |
| `mode(variable)` | браузер | Самое частое значение, а при равных частотах — все такие значения |
| `modefreq(variable)` | браузер | Частота моды |

### Описательные статистики

`mean`, `sd`, `var`, `se`, `median`, `iqr`, `min`, `max`, `skew`, `kurtosis` — каждая функция принимает одну переменную и вычисляется в браузере по тому же объекту, из которого берёт числа карточка описательных статистик. `kurtosis` возвращает эксцесс (куртозис минус 3), как и карточка.

### Направление

| Примитив | Где | Возвращает |
|---|---|---|
| `argmax_level(group, variable, stat)` | браузер | Уровень с наибольшим значением `'mean'` или `'median'`, а при равенстве — все такие уровни |
| `argmin_level(group, variable, stat)` | браузер | Уровень с наименьшим значением, по тому же правилу |
| `sign(value)` | браузер | `'+'` или `'−'` |
| `direction(outcome, condition, from, to, stat)` | браузер | `'up'` или `'down'` — рост или снижение между двумя условиями |
| `contains(list, value)` | браузер | Проверка вхождения для примитивов, которые возвращают список |

Аргумент `stat` обязателен для обеих функций поиска крайнего уровня: по среднему и по медиане крайними могут оказаться разные уровни, а ключ ответов не может полагаться на неявное значение по умолчанию.

### Нормальность, сравнение, корреляция

| Примитив | Где | Возвращает |
|---|---|---|
| `normaltest(variable, test)` | R | `.p`, `.stat` |
| `compare2(group, variable, test)` | R | `.p`, `.stat`, `.effect` |
| `compareK(group, variable, test)` | R | `.p`, `.stat` |
| `posthoc(group, variable, test, method)` | R | Таблица пар, к строкам которой обращаются по паре из `pairs(levels(g))` |
| `within2(outcome, condition, subject, test)` | R | `.p`, `.stat` |
| `withinK(outcome, condition, subject, test)` | R | `.p`, `.stat`, а для дисперсионного анализа с повторными измерениями также `.pGG` / `.pHF` |
| `posthocWithin(outcome, condition, subject, test, method)` | R | Таблица пар |
| `cor(x, y, method)` | R | `.r`, `.p` |

Трём примитивам для повторных измерений нужны условие и идентификатор испытуемого, а они есть только в данных, построенных по спецификации `design`.

### Факторный анализ и надёжность

| Примитив | Где | Возвращает |
|---|---|---|
| `efa(items, k, extraction, rotation)` | R | `.loadings`, `.grouping` |
| `sameFactor(items, k, extraction, rotation, anchor)` | R | Пункты, попавшие на один фактор с `anchor` |
| `loading(items, k, extraction, rotation, item)` | R | Абсолютная величина наибольшей нагрузки этого пункта |
| `suggestK(items, extraction, reference)` | R | Число факторов, которое оставляет параллельный анализ |
| `reliability(items, reversed?)` | R | `.alpha`, `.itemTotal[item]`, `.alphaIfDeleted[item]` |

`reversed` — список обратных пунктов: перед расчётом они перекодируются. Так найденные студентом обратные пункты сочетаются со шкалой, которую он собрал сам: `reliability(@kept, @rev).alpha`.

> **Никогда не спрашивайте номер фактора.** Фактор 1 на вашем экране может оказаться фактором 2 у другого студента: порядок факторов произволен. Указывайте фактор через пункт (*какие пункты относятся к тому же фактору, что и пункт 3?*) и спрашивайте нагрузки по модулю. Для этого и предназначены `sameFactor` и `loading`.

### Регрессия

| Примитив | Где | Возвращает |
|---|---|---|
| `regress(outcome, predictors, type)` | R | Строка сводки по модели — `.n`, `.p`, `.stat`, `.df`, `.dfResidual` и показатели, свойственные семейству |
| `coef(outcome, predictors, type, predictor, level?)` | R | Строка одного коэффициента — `.b`, `.beta`, `.se`, `.stat`, `.p`, `.or` |
| `vif(outcome, predictors, type, predictor)` | R | Коэффициент инфляции дисперсии этого предиктора |

Все три примитива берут результат одной и той же подгонки, а подгонка кэшируется по **модели**. Поэтому вопрос о модели и затем о каждом её предикторе обходится одним обращением к движку, а не отдельным на каждый предиктор.

`type` задаёт семейство: `linear`, `binomial`, `ordinal`, `poisson` или `negbinomial`. Это намеренно выбранное **подмножество** семейств модуля регрессии. Исключены семейства, у которых нет единственной строки коэффициентов: мультиномиальная модель выводит отдельную таблицу коэффициентов для каждого контраста исхода, а двухчастная модель для счётных данных — таблицу счётной части рядом с таблицей нулей.

**Набор полей подгонки зависит от семейства: поля, которые семейство не вычисляет, просто отсутствуют.**

| Поле | Семейство | Значение |
|---|---|---|
| `.n` | любое | Число наблюдений, по которым подогнана модель |
| `.p` `.stat` `.df` `.dfResidual` | любое | Общий критерий и его степени свободы |
| `.aic` `.bic` | любое | Информационные критерии |
| `.r2` `.adjR2` `.f2` `.rootMSE` | `linear` | R², скорректированный R², f² Коэна, корень из среднеквадратичной ошибки |
| `.mcfaddenR2` `.adjMcfaddenR2` `.nagelkerkeR2` `.coxSnellR2` | остальные четыре | Псевдо-R² |
| `.deviance` `.nullDeviance` `.logLik` | остальные четыре | Остаточный девианс, нулевой девианс, логарифм правдоподобия |

`.stat` и `.df` относятся к тому общему критерию, который применяет семейство: к F-критерию и степеням свободы числителя в линейной модели, к χ² отношения правдоподобия и его степеням свободы в остальных. Поэтому одно и то же выражение берёт нужную статистику при любом семействе. С `.r2` всё наоборот: это поле есть только у линейной модели, чтобы псевдо-R² никогда не оказался под именем, которое означает другое.

> **Доверительных интервалов нет.** Недоступны ни интервал для R², ни ДИ коэффициентов. Из чисел регрессии только они зависят от настройки **Уровень доверия**, а лист ответов её не сохраняет, поэтому вопрос на их основе оценивался бы по-разному до и после того, как студент изменит настройку. `cor` и `reliability` точно так же не дают доступа к своим ДИ.

В строке коэффициента `.b` — нестандартизованный коэффициент, `.beta` — стандартизованный. `.or` — экспонента коэффициента: отношение шансов для `binomial` и `ordinal`, отношение интенсивностей для `poisson` и `negbinomial`. У `linear` этого поля нет, потому что у линейной модели нет шкалы отношений.

**У категориального предиктора нет единственного коэффициента,** потому что R кодирует его контрастными столбцами, по одному на уровень, и карточка выводит строку для каждого из них. Поэтому у `coef` есть пятый аргумент — уровень, записанный точно так же, как на карточке:

```json5
truth: { b: "coef(income, vars('age','sex'), 'linear', sex, 'male').b" }
```

`levels()` возвращает те же имена, поэтому в `table` можно вычислить `coef` по всем уровням фактора, подставив `$row` на место уровня, если опорного уровня среди строк нет. С этим аргументом связаны три правила, и при нарушении любого из них сообщается причина, а не возвращается пустой ответ:

- **Числовому предиктору уровень не указывают** — у него и так одна строка, и указанный уровень считается ошибкой.
- **Категориальному предиктору уровень необходим** — без уровня нет единственной строки, из которой берётся значение.
- **У опорного уровня коэффициента нет вовсе** — R включает его в свободный член. Это первый уровень **в порядке сортировки**, а не в том порядке, в каком уровни перечислены в спецификации, поэтому выясните, какой уровень опорный, прежде чем строить вопросы по остальным.

`vif` — исключение из всех этих правил: у него четыре аргумента и никакого уровня. Пакет `car` сводит контрастные столбцы категориального предиктора в одну строку GVIF, поэтому предиктор, которому для `coef` нужен уровень, в `vif` рассматривается как одна переменная.

### Идентификаторы методов

Названия критериев, методов, способов извлечения и вращения — это внутренние идентификаторы приложения, поэтому вопрос называет именно то, что выбирает студент. Автодополнение редактора предлагает допустимые значения **для каждой позиции аргумента** и берёт их из тех же справочников, что и сам анализ: `compare2` предлагает только критерии для двух выборок, `compareK` — только общие критерии, а `posthoc` — только методы, объявленные для его общего критерия. Самые употребительные: `mannWhitneyU`, `welchTTest`, `independentTTest`, `kruskalWallis`, `oneWayANOVA`, `wilcoxonSignedRank`, `pairedTTest`, `friedmanTest`, `repeatedMeasuresANOVA`, `tukey`, `dunn`, `pearson`, `spearman`, `shapiroWilk`.

## Проверка вопросов

**Вычислить ключ ответов** — эта кнопка генератора экзаменов создаёт пример набора данных, вычисляет на нём все эталоны и выводит по строке на каждую строку ответа. Проверяйте так каждый вопрос перед экспортом ссылки: только так обнаруживается вопрос, который компилируется, но ничего не вычисляет.

У выбора эталона нет, поэтому ключ берёт за ответ первый вариант, а при `n: "any"` — всю область. Затем ключ каждого оцениваемого вопроса подставляется как ответ студента, и построенные на нём вопросы вычисляются, а не сообщают об ожидании.

Нажмите **Пересоздать** в просмотре и вычислите ключ заново, чтобы увидеть, насколько ответы меняются от студента к студенту. Если ответом на вопрос-множество каждый раз оказывается вся область, эффект слишком велик и вопрос теряет смысл.

## Советы

**Называйте нужный столбец.** Для переменной с пропусками выводятся два процента, а на карточке надёжности три столбца корреляций пункт–сумма. Эталон берёт один из них, и текст вопроса должен назвать, какой именно, иначе студент выбирает между двумя одинаково обоснованными ответами. Предпочитайте `validPercent`, а если имеете в виду `.itemTotal`, пишите «скорректированная корреляция пункт–сумма».

**`.p` — это скорректированное p везде, где оно вычислено.** При [поправке на множественные сравнения](./settings.md#поправка-на-множественные-сравнения) карточка выводит оба столбца, а эталон берёт скорректированный, то есть то самое число, которое студент видит в результатах только что выполненного анализа.

**`.p` в дисперсионном анализе с повторными измерениями — нескорректированное значение.** Карточка выводит p, p (GG) и p (HF) рядом, поэтому укажите в вопросе, какое из них нужно, и берите его через `.p`, `.pGG` или `.pHF`.

**Не используйте `.effect` в оцениваемых эталонах.** Часть размеров эффекта вычисляется бутстрэпом, и если [зерно бутстрэпа](./settings.md#зерно-бутстрэпа) не задано, два запуска одного анализа дают разные значения. `.p` и `.stat` вычисляются по формуле и воспроизводятся точно.

**Задавайте эффекты с запасом от пороговых значений.** Если при заданном эффекте в генеральной совокупности у типичного студента p оказывается около 0.05, ответ на вопрос становится делом случая. Если вам нужен вопрос, ответ на который действительно различается у студентов, пусть это будет осознанный *выбор*: задайте для него малый эффект, а не полагайтесь на случай при большом.

**Одна ссылка на блок заданий.** Ссылка передаёт один набор данных, поэтому вопросы, которым нужна другая структура данных (повторные измерения, другая группирующая переменная), выносите в отдельную ссылку с собственной спецификацией.

## Что выбрать

**`set` или `table`?** В множестве студент отмечает, *какие* элементы подходят. В таблице он указывает, *каковы* значения — одно или несколько для каждого элемента. Множество даёт одну отметку, а таблица оценивается по ячейкам и поэтому даёт больше обратной связи. Если к вопросу естественно добавить «и укажите r и p для каждой», нужна таблица.

**Скаляр с p-значением или `value` с ответом «да» / «нет»?** Если студент видит p-значения в виде категорий, а не точных чисел, на вопрос-скаляр о p-значении ответить нельзя. Вопрос `value` с вариантами `['да','нет']` о том, значим ли результат при заданном α, работает при любых настройках отображения, и обычно проверить нужно именно это.

**Зафиксировать выбор или оставить его студенту?** Фиксируйте, если сам выбор не входит в проверяемые навыки. Вопрос `pick` оправдан, когда на нём строятся следующие вопросы: у каждого студента получается своя цепочка, и вы оцениваете студента по шкале, которую собрал *он сам*, а не вы.

**Какой вес придать счёту?** Это решаете вы, и под любой вариант блок подходит без изменений в спецификации. Счёт `passed / total` на панели учитывает только оцениваемые вопросы, а `gate` не зависит от оценивания, поэтому один и тот же блок годится для трёх совсем разных курсов. Если оценкой служат сами числа, оценивайте каждый вопрос, не добавляйте вопросов для письменного ответа и поставьте `gate: "export"` с `threshold: 1`: экспорт откроется, только когда все ответы верны. Если числа — лишь условие допуска, а оценивается интерпретация, основной вес приходится на письменные ответы, а панель только подтверждает, что анализ выполнен правильно. Возможна и смесь: при `gate: "warn"` студент может сдать и неполную работу, а вес частей определяете вы. Курсы различаются не спецификацией, а тем, что вы скажете студентам о смысле панели: страница [Прохождение экзамена](./taking-an-exam.md) объясняет им механику, а эту часть оставляет вам.
