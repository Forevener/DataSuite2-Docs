# Справочник по вопросам экзамена

Экзамен добавляет к спецификации генератора блок `exam`. В блоке лежит список вопросов; каждый из них говорит, что вводит студент и как правильный ответ вычисляется по **его** набору данных. Поскольку данные каждого студента разыгрываются из его собственного имени, ключ ответов вычисляется отдельно для каждого, а не записывается заранее – вы пишете вопрос, а не ответ.

Вопросы компилируются при экспорте ссылки, поэтому опечатка в имени переменной или неизвестный метод обнаруживаются в редакторе, а не у студента.

> Эта страница – про вопросы. Про сам набор данных – факторы, переменные, группы, распределения, планы – см. [справочник по спецификации экзамена](./exam-spec-reference.md). Про то, что видит студент, – [прохождение экзамена](./taking-an-exam.md).

## Быстрый старт

```json5
exam: {
	gate: "warn", threshold: 1,
	questions: [
		{
			id: "q1",
			text: "Какие шкалы различаются между мужчинами и женщинами? (Манна–Уитни, α = 0.05)",
			answer: { type: "set", over: "vars('PF','GH','MH')" },
			truth: { over: "vars('PF','GH','MH')", where: "compare2(sex, $v, 'mannWhitneyU').p < 0.05" },
		},
	],
}
```

Вот и вся форма: `answer` описывает элемент ввода, `truth` – вычисление. Нажмите **Вычислить ключ ответов** в генераторе экзаменов, чтобы прогнать все эталоны по образцу набора данных до экспорта.

## Блок exam

| Поле | Значение |
|---|---|
| `gate` | Что непройденный порог делает с экспортом в Word – `"export"` блокирует его, `"warn"` запрашивает подтверждение, `"none"` игнорирует |
| `threshold` | Доля оцениваемых вопросов, которые должны быть пройдены, по умолчанию `1` (все) |
| `questions` | Упорядоченный список – порядок и видит студент, и по нему разрешаются ссылки `@qN` |

Вопросы-выборы и вопросы с письменным ответом в счёт не идут, поэтому `threshold: 1` означает все *оцениваемые* вопросы.

## Вопрос

| Поле | Обязательно | Значение |
|---|---|---|
| `id` | да | Как на этот вопрос ссылаются последующие (`@q1`). Должен быть уникальным |
| `text` | да | Показывается студенту дословно и **не переводится** – пишите на языке, на котором преподаёте |
| `answer` | да | Элемент ввода и способ сверки |
| `truth` | кроме `pick` / `prose` | Выражение, вычисляющее правильный ответ |
| `scope` | нет | Ограничивает эталон подмножеством строк |

Метод живёт в тексте вопроса. В самом языке нет ничего, что спрашивало бы, *какой критерий уместен*: критерий, односторонность, апостериорный метод и α вы фиксируете формулировкой, а дело студента – корректно всё это выполнить.

## Типы ответов

| `type` | Элемент ввода | Как сверяется |
|---|---|---|
| `scalar` | текстовое поле | Значение в том виде, в каком его **показывает** приложение, при собственных настройках точности студента |
| `value` | выпадающий список | Точное совпадение |
| `set` | список флажков | Точное совпадение множеств – оценивается целиком |
| `table` | сетка, по строке на элемент | По ячейкам; вопрос пройден, когда пройдена каждая ячейка |
| `pick` | список или флажки | Не оценивается – это ввод, который читают последующие вопросы |
| `prose` | строка-напоминание | Не оценивается – вы читаете его в документе |

### `scalar`

```json5
answer: { type: "scalar" }                    // сверяется по отображаемому значению
answer: { type: "scalar", tol: 0 }            // точно – для частот
answer: { type: "scalar", kind: "pvalue" }    // формат p-значения и правило нижней границы
```

- `tol` – принимать всё, что отличается от эталона не более чем на эту величину. `tol: 0` означает точное совпадение. Опустите его – и эталон будет отформатирован собственным форматировщиком приложения и сверен как текст, что и делает правилом «вводите то, что показывает экран».
- `kind` – по какой категории точности форматировать: `descriptive` (по умолчанию), `statistic` или `pvalue`. Ячейка `pvalue` дополнительно принимает всё, что не превышает нижнюю границу отображения, потому что `< 0.001` – это всё, что там показывает экран.

### `value`

```json5
answer: { type: "value", from: "levels(sex)" }
answer: { type: "value", from: ["yes", "no"] }
```

`from` – это [область](#области). Обычный массив задаёт список литеральных ответов.

### `set`

```json5
answer: { type: "set", over: "numericVars" },
truth:  { over: "numericVars", where: "compare2(sex, $v, 'mannWhitneyU').p < 0.05" }
```

Эталон имеет вид `{ over, where }`, где `$v` по очереди связывается с каждым элементом; ответ – те элементы, для которых `where` истинно. Множество оценивается целиком – отметок по отдельным элементам нет, поэтому непройденное множество отправляет студента обратно к его собственной таблице вывода, а не выдаёт ответ по одному флажку за проверку.

Область одновременно является пакетом: все её элементы уходят в модуль анализа одним запуском – это и то, о чём просит текст вопроса («выберите все эти переменные и запустите один раз»), и то, что делает поправку на множественность корректной.

### `table`

```json5
answer: {
	type: "table",
	rows: "vars('O','C','E','A','N')",
	cols: {
		r: { type: "scalar", kind: "statistic" },
		p: { type: "scalar", kind: "pvalue" },
		significant: { type: "value", from: ["yes", "no"] },
	},
},
truth: {
	r: "cor(age, $row, 'pearson').r",
	p: "cor(age, $row, 'pearson').p",
	significant: "if(cor(age, $row, 'pearson').p < 0.05, 'yes', 'no')",
}
```

По строке на каждый элемент `rows`, по одной типизированной ячейке на столбец – ячейки бывают `scalar` или `value`. Эталон – по одному выражению на столбец, где `$row` связан с элементом строки. Выражение нужно каждому ключу столбца.

### `pick`

```json5
answer: { type: "pick", from: "@q2" }                      // один из прежних ответов студента
answer: { type: "pick", from: "items('A')", n: "any" }     // любое их число
answer: { type: "pick", from: "numericVars", n: 3 }        // ровно три
```

У выбора **нет эталона**, и он никогда не отмечается. Он нужен, чтобы следующие за ним вопросы работали с собственным выбором студента – *выберите одну из шкал, которые вы только что перечислили*, затем *у какого пола она выше?* Используйте `distinct: true`, чтобы запретить повторы, когда несколько выборов делят одну область.

### `prose`

```json5
answer: { type: "prose" }
```

Ни элемента ввода, ни эталона – строка, напоминающая студенту описать это словами. В выгруженном листе ответов она появляется с пометкой, что не оценивается.

## Эталонные выражения

Эталон – это небольшое выражение, записанное строкой:

- числа, `'строки в кавычках'` и голые имена столбцов (`age`, `PF`, `sex`)
- `$v` (текущий элемент множества) и `$row` (текущая строка таблицы)
- `@qN` – ответ студента на более ранний вопрос
- вызовы примитивов с позиционными аргументами – `compare2(sex, PF, 'mannWhitneyU')`
- обращение к полю – `.p`, `.r`, `.alpha`; и индексация по элементу – `.itemTotal[$v]`, `[$v]`
- сравнения `== != < <= > >=`, `and` / `or` / `not` и `if(условие, a, b)`

Ни переменных, ни циклов, ни собственных функций здесь нет – [каталог примитивов](#каталог-примитивов) и есть весь язык.

Эталон может вычислиться в **список допустимых ответов**, и тогда проходит любой его элемент. Так обрабатываются связи: `mode` возвращает все совпавшие по частоте значения, а помощники поиска крайней группы – все совпавшие уровни, так что собственного правила для связей вам не нужно.

## Области

Область – это то, по чему пробегает `set`, что предлагает `value` или `pick` и чем являются строки `table`. Это выражение, ровно как и эталон:

| Область | Что даёт |
|---|---|
| `vars('PF','GH','MH')` | эти столбцы, перечисленные поимённо |
| `items('SF')` | все столбцы блока пунктов из спецификации |
| `numericVars` | все числовые столбцы |
| `allVars` | все столбцы |
| `outcomes` | столбцы-исходы спецификации с блоком `design` |
| `levels(sex)` | уровни группирующего или внутригруппового фактора |
| `pairs(levels(site))` | неупорядоченные пары списка уровней – для апостериорных вопросов |
| `@q2` | ответ студента на более ранний `set` или `pick` |
| `['yes', 'no']` | литеральные значения |

> **Единственная ловушка, которую стоит запомнить:** **массив** JSON5 – это список литеральных значений, но никогда не список столбцов. `rows: ['PF','GH']` даст две строки, подписанные строками `PF` и `GH`; `rows: "vars('PF','GH')"` даст два столбца. Когда нужны столбцы, пишите выражение.

## Ссылки и ограничение строк

`@qN` указывает на более ранний вопрос и никогда на более поздний – компилятор отвергает ссылку вперёд и ссылку в никуда. Внутри эталона она разрешается в значение: столбец для выбора переменной, уровень для выбора уровня, множество для ответа-множества.

```json5
{ id: "q3", text: "У какого пола она выше?",
  answer: { type: "value", from: "levels(sex)" },
  truth: "argmax_level(sex, @q2, 'median')" }
```

Вопрос, чья *область* названа через более ранний ответ, показывает строку ожидания, пока на тот вопрос не ответят. Вопрос, который лишь *читает* более ранний ответ в своём эталоне, отображается и отвечается как обычно – ожидание сообщает только его проверка.

`scope` ограничивает строки, по которым считается эталон, повторяя диалог **Наблюдения** один в один, так что текст вопроса может назвать точный фильтр, который студенту нужно выставить:

```json5
scope: { country: ['France', 'Spain'] }   // категориальный: эти уровни
scope: { country: '@q4' }                 // уровни, выбранные студентом
scope: { age: [30, null] }                // числовой диапазон, null – открытая граница
scope: { age: { min: 30, max: 60 } }      // то же самое, развёрнуто
```

## Каталог примитивов

Всё перечисленное работает на замороженной копии набора данных студента. Столбец **Где** говорит, вычисляется ли примитив в браузере или передаётся модулю анализа, которому он принадлежит: примитивы на R стоят одного обращения к движку, поэтому построенный на них вопрос проверяется секунду-другую.

### Подсчёт

| Примитив | Где | Возвращает |
|---|---|---|
| `nrows()` | браузер | Число строк в области |
| `count(predicate)` | браузер | Число подходящих строк, например `count(sex == 'female')` |
| `percent(predicate)` | браузер | Процент от **всех** строк |
| `validPercent(predicate)` | браузер | Процент от строк без пропусков в предикате |
| `prop(predicate)` | браузер | `validPercent` в виде доли |
| `freq(variable)` | браузер | Таблица частот |
| `mode(variable)` | браузер | Самое частое значение – все совпавшие по частоте |
| `modefreq(variable)` | браузер | Как часто встречается мода |

### Описательные статистики

`mean`, `sd`, `var`, `se`, `median`, `iqr`, `min`, `max`, `skew`, `kurtosis` – каждая берёт одну переменную и считается в браузере, из того же объекта, который печатает карточка описательных статистик. `kurtosis` – это эксцесс, как и на карточке.

### Направление

| Примитив | Где | Возвращает |
|---|---|---|
| `argmax_level(group, variable, stat)` | браузер | Уровень с наибольшим `'mean'` или `'median'` – все совпавшие уровни |
| `argmin_level(group, variable, stat)` | браузер | Наименьший, по тому же правилу |
| `sign(value)` | браузер | `'+'` или `'−'` |
| `direction(outcome, condition, from, to, stat)` | браузер | `'up'` или `'down'` между двумя условиями |
| `contains(list, value)` | браузер | Проверка вхождения – для примитива, отвечающего списком |

Аргумент `stat` обязателен у обоих крайних уровней: среднее и медиана могут назвать разные уровни, а молчаливого умолчания ключ ответов позволить себе не может.

### Нормальность, сравнение, корреляция

| Примитив | Где | Возвращает |
|---|---|---|
| `normaltest(variable, test)` | R | `.p`, `.stat` |
| `compare2(group, variable, test)` | R | `.p`, `.stat`, `.effect` |
| `compareK(group, variable, test)` | R | `.p`, `.stat` |
| `posthoc(group, variable, test, method)` | R | Таблица пар – индексируйте её парой из `pairs(levels(g))` |
| `within2(outcome, condition, subject, test)` | R | `.p`, `.stat` |
| `withinK(outcome, condition, subject, test)` | R | `.p`, `.stat`, а для дисперсионного анализа с повторными измерениями ещё `.pGG` / `.pHF` |
| `posthocWithin(outcome, condition, subject, test, method)` | R | Таблица пар |
| `cor(x, y, method)` | R | `.r`, `.p` |

Внутригрупповой тройке нужны условие и идентификатор испытуемого, а их даёт только спецификация с блоком `design`.

### Факторный анализ и надёжность

| Примитив | Где | Возвращает |
|---|---|---|
| `efa(items, k, extraction, rotation)` | R | `.loadings`, `.grouping` |
| `sameFactor(items, k, extraction, rotation, anchor)` | R | Пункты, попавшие на фактор вместе с `anchor` |
| `loading(items, k, extraction, rotation, item)` | R | Модуль наибольшей нагрузки этого пункта |
| `suggestK(items, extraction, reference)` | R | Число факторов, оставленных параллельным анализом |
| `reliability(items, reversed?)` | R | `.alpha`, `.itemTotal[item]`, `.alphaIfDeleted[item]` |

`reversed` – список пунктов, которые надо предварительно перекодировать в обратную сторону, поэтому найденные студентом обратные пункты сочетаются с выбранной им шкалой: `reliability(@kept, @rev).alpha`.

> **Никогда не спрашивайте номер фактора.** Фактор 1 на вашем экране – это фактор 2 на чужом: порядок произволен. Вместо этого закрепляйте фактор пунктом (*какие пункты грузятся на тот же фактор, что и пункт 3?*) и спрашивайте нагрузки по модулю. `sameFactor` и `loading` существуют ровно для этого.

### Идентификаторы методов

Названия критериев, методов, извлечения и вращения – это собственные идентификаторы приложения, поэтому вопрос называет ровно то, что выбирает студент. Автодополнение редактора предлагает допустимый набор **для каждой позиции аргумента**, читая его из тех же справочников, что использует сам анализ: `compare2` предлагает только критерии для двух выборок, `compareK` – только общие критерии, а `posthoc` – только те методы, которые объявляет его общий критерий. Часто встречающиеся: `mannWhitneyU`, `welchTTest`, `independentTTest`, `kruskalWallis`, `oneWayANOVA`, `wilcoxonSignedRank`, `pairedTTest`, `friedmanTest`, `repeatedMeasuresANOVA`, `tukey`, `dunn`, `pearson`, `spearman`, `shapiroWilk`.

## Проверка ваших вопросов

**Вычислить ключ ответов** в генераторе экзаменов создаёт образец набора данных и прогоняет по нему все эталоны, печатая по строке на каждую строку ответа. Пользуйтесь этим на каждом вопросе перед экспортом ссылки – только так ловится вопрос, который компилируется, но ничего не вычисляет.

У выбора эталона нет, поэтому ключ берёт первый вариант – или, при `n: "any"`, всю область. Затем ключ каждого оцениваемого вопроса используется как ответ этого студента, так что построенные на нём вопросы разрешаются, а не сообщают об ожидании.

Нажмите **Пересоздать** в просмотре и пересчитайте ключ, чтобы увидеть, насколько ответы гуляют от студента к студенту. Множество, ответом на которое каждый раз оказывается вся область, означает, что ваш эффект слишком велик, чтобы вопрос был интересным.

## Советы

**Называйте нужный столбец.** У переменной с пропусками печатаются два процента, а карточка надёжности печатает три столбца корреляций пункт–сумма. Эталон выбирает один; текст вопроса обязан сказать, какой именно, иначе студент выбирает между двумя одинаково защитимыми ответами. Предпочитайте `validPercent`, а имея в виду `.itemTotal`, говорите «скорректированная корреляция пункт–сумма».

**`.p` – это скорректированное p везде, где расчёт его дал.** При включённой [поправке на множественную проверку](./settings.md#поправка-на-множественную-проверку) карточка печатает оба столбца, а эталон читает скорректированный – то самое число, на которое смотрит студент, читая только что запущенное им семейство.

**`.p` у дисперсионного анализа с повторными измерениями – нескорректированный столбец.** Карточка печатает p, p (GG) и p (HF) рядом, поэтому скажите, какой из них вам нужен, и читайте его через `.p`, `.pGG` или `.pHF`.

**Держите `.effect` вне оцениваемых эталонов.** Часть размеров эффекта берётся с бутстрэпа, и без заданного [зерна бутстрэпа](./settings.md#зерно-бутстрэпа) они различаются между двумя запусками одного и того же анализа. `.p` и `.stat` имеют замкнутую форму и безопасны.

**Задавайте эффекты с хорошим запасом от порогов.** Популяционный эффект, приводящий среднего студента к p = 0.05, превращает вопрос в подбрасывание монеты. Если вам нужен вопрос, ответ на который действительно различается у студентов, это *выбор* – делайте его намеренно, на небольшом эффекте, а не случайно на большом.

**По одной ссылке на блок заданий.** Ссылка несёт один набор данных, поэтому вопросы, которым нужна другая структура – повторные измерения, другая группирующая переменная, – место в собственной ссылке с собственной спецификацией.

## Что выбрать

**`set` или `table`?** Множество спрашивает *какие* – студент отмечает подходящие элементы. Таблица спрашивает *что* – одно или несколько значений на элемент. Множество – это одна отметка, таблица оценивается по ячейкам и поэтому даёт больше обратной связи. Если у вопроса естественно возникает «и укажите r и p для каждого», это таблица.

**Скаляр с p-значением или `value` с «да / нет»?** Если студент работает с p-значениями, отображаемыми категориями, а не точными числами, скаляр с p-значением ответить нельзя. Вопрос типа `value` над `['yes','no']`, спрашивающий, значим ли результат при α, работает при любых настройках отображения и обычно именно то, что вы и хотите проверить.

**Зафиксировать выбор или отдать его студенту?** Фиксируйте, если только сам выбор не является проверяемым навыком. Вопрос-выбор оправдывает себя, когда на нём строятся следующие вопросы: он делает цепочку каждого студента его собственной и позволяет оценивать студента по шкале, которую собрал *он*, а не вы.
